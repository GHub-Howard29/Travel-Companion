# V3.9.24 PWA 更新偵測與接管重試修復紀錄

> 狀態：2026-10-07 已完成實作、專項 regression、完整 production build、瀏覽器跨版本模擬與正式 GitHub Pages 部署。正式 source commit 為 `c7ada6c`，GitHub Pages commit 為 `8b3b060`。

## 問題現象

V3.9.23 正式部署後，Android PWA 可能仍停留在舊版本；即使已出現更新提示，按下更新後也可能：

1. 顯示「等待新版接管」數秒。
2. 回到「重試更新」。
3. 再按一次後仍重複相同流程。
4. 實際上新版 Service Worker 可能已經下載甚至進入 `active`，但目前頁面仍由舊 controller 控制。

這與 V3.9.21 的 Service Worker handoff 問題屬同一類時序問題，但本次根因不同。

## 根因

### 1. 啟動時未主動檢查新版 Service Worker

舊流程在 App 啟動時會查 `app-version.json`，但取得 Service Worker registration 後沒有立即執行 `registration.update()`。

因此：

- 正式站 metadata 已是新版，不代表手機 PWA 已下載新版 worker。
- 若裝置一直在線，沒有新的 `online` event，則只能依賴 Chrome 自行決定何時檢查 `sw.js`。
- 使用者可能長時間維持舊 controller，即使伺服器早已完成部署。

### 2. 已 active 的新版 worker 被誤判成「尚未下載完成」

V3.9.22 後的更新流程只將以下狀態視為新版已準備好：

- `registration.waiting`
- `registration.installing`
- `onNeedRefresh` 已觸發

但實際裝置可能存在：

- `registration.active` 已經是新版 worker
- `navigator.serviceWorker.controller` 仍是舊 worker
- `waiting === null`
- `installing === null`

此時舊流程會等不到 waiting/installing，最後逾時並顯示「重試更新」。

### 3. handoff helper 只在 controller 完成切換時提前結束

原本 `waitForServiceWorkerHandoff()` 的輪詢只在狀態為 `controlled` 時提前完成；即使 helper 已能辨識 `active`，也可能繼續等待 timeout。

## V3.9.24 修正

### 主動更新偵測

- Service Worker 註冊完成後，若在線，立即主動執行一次 `registration.update()`。
- App 從背景回到前景時，同步重新檢查版本 metadata 與 Service Worker。
- 前景檢查採 30 秒節流，避免頻繁請求 `sw.js`。
- 離線轉在線時強制執行一次更新檢查。

### active-worker 狀態補強

- `waitForUpdateWorkerReady()` 新增 `previousController` 判斷。
- 若 `registration.active !== previousController` 且新 active worker 已為 `activated`，直接視為新版已準備完成。
- 若新版已 active、且沒有 waiting/installing，但舊頁面仍由舊 controller 控制，直接進入 `ready-to-reload`。
- 不再把這種合法狀態誤報成「新版尚未下載完成」。

### handoff 結束條件

- handoff 輪詢由只接受 `controlled` 改為接受 helper 回傳的任何有效 handoff 狀態。
- 新 worker 已 active 時可立即結束等待，不必等 12 秒 timeout。

### 第二次按鈕行為

當畫面已進入「重新載入套用新版」：

- 第二次按鈕直接驗證 active worker 後 reload。
- 不再重新執行 Trip 資料 preflight、metadata check、下載與接管流程。

## 驗證

### 自動回歸

新增：

`npm run verify:v3924-update-handoff`

驗證：

- 註冊完成後主動檢查 worker。
- 回到前景時主動檢查。
- 30 秒節流存在。
- active replacement worker 被正確視為 ready。
- active-but-not-controller 狀態直接進入 ready-to-reload。
- handoff helper 不再固定等待 timeout。
- 第二次重新載入按鈕不再重跑 preflight。

既有 `verify:v3913-update-race` 同時通過。

## 後續實機觀察

瀏覽器已完成跨版本接管模擬，但 Android 安裝型 PWA 仍應觀察真實 V3.9.23 → V3.9.24 更新：

1. 開啟 PWA 後應能較快偵測新版，不必等待 Chrome 自行排程。
2. 按一次更新不得回到「重試更新」循環。
3. 若顯示「重新載入套用新版」，再次按下應直接進入新版。
4. 更新後應顯示 V3.9.24，且不需要手動清除網站資料或重新安裝 PWA。
5. 冷啟動、離線啟動與 V3.9.23 已修正的本機快取行為不得回歸。
