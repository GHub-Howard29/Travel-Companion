# 資料復原與離線救援操作

> 本文件是每日行程歷程、完整資料快照與離線救援的現行操作入口。V3.9.7 已於 2026-09-24 正式發布；版本專屬設計與發布證據見《[archive/v3.9.7/](archive/v3.9.7/)》。

## 適用範圍與安全邊界

- 每日行程歷程只保存 `trips.content.daysData` 中被修改 Day 的變更前卡片陣列；同一 Trip、同一 Day 每個整點最多一份，最近保留 30 份。
- 每日完整應用資料快照保留最近 7 份成功快照；附件只保護引用與中繼資料，並不保存附件二進位檔。
- 離線救援工具僅唯讀擷取目標 Trip 的 Local Storage allowlist；不啟動 PWA、不使用 Supabase、沒有網路模組，也不輸出登入權杖。
- 任何資料庫寫入、完整還原、`pre_restore`、Storage 清理或權限復原，都需要該次明確授權；不可用來源不明或未比對的 JSON 覆寫雲端。

## 事故前歷程不存在時：離線救援

工具原始碼位於 `tools/offline-itinerary-rescue`。在目標電腦執行前，先中斷網路並完全關閉 PWA、Chrome 與 Edge；工具會將 LevelDB 複製到系統暫存區並比對來源指紋，原始瀏覽器資料不會被修改。

```powershell
npm ci --prefix tools/offline-itinerary-rescue --ignore-scripts
node tools/offline-itinerary-rescue/verify-rescue.mjs
node tools/offline-itinerary-rescue/build-portable.mjs
```

Windows x64 可攜 ZIP 位於 `.release/TravelCompanion-Itinerary-Rescue-v1.1.0-win-x64.zip`。救援包可能包含參與者 Email、帳本與私人清單，須儲存在受信任且受保護的位置。

## 唯讀列出每日行程歷程

先以當次明確提供的資料庫連線資訊讀取歷程；工具不會將連線字串寫入檔案。

```powershell
$env:TRAVEL_COMPANION_DATABASE_URL = '<當次核准的資料庫連線字串>'
npm run itinerary:history -- list --trip group-tour-2026-10 --day 1
```

輸出包含歷程 ID、快照及目前版本時間、卡片數、標題、寫入者／來源 client ID，以及相對目前 Day 的差異摘要。

## 單一 Day 受控復原

1. 先執行 `list`，人工核對 Trip、Day、歷程時間、標題與差異。
2. 取得 `currentUpdatedAt` 後，在正式寫入前再次讀取並確認未變更。
3. 取得該次寫入授權後，輸入精確二次確認字串。

```powershell
npm run itinerary:history -- restore --trip group-tour-2026-10 --day 1 --history-id 123 --expected-updated-at 2026-09-24T00:00:00.000000+00:00 --confirm "RESTORE group-tour-2026-10 DAY 1 FROM 123"
```

還原在單一交易內以 `updated_at` 樂觀鎖定，只替換指定 Day；版本歷程與 revision 機制會通知其他裝置重新載入。

## 完整快照與完整復原

- 快照維運工具可列出快照，或在任何大量寫入前建立 `pre_restore`：

```powershell
npm run snapshot:admin -- list
npm run snapshot:admin -- create-pre-restore "全域復原前"
```

- 完整復原必須依序完成：驗證快照／救援包 checksum 與 schema、唯讀差異預覽、再次讀取目前資料、建立並驗證 `pre_restore`、精確二次確認、寫入後回讀驗證。
- 停止操作的條件包括：來源無法證明正確、樂觀鎖已改變、差異超出預期 Trip／資料域，或尚未取得當次正式寫入授權。
