# V3.9.13 Commons 分類中文判讀與候選批次修正規格

> 狀態：發布前驗證中。PWA 更新／遠端 Trip 修訂競態、Commons 分類翻譯 fallback、batch v2 後端契約與正式 `ItineraryPage` UI 均已完成；Product Owner 已核准 UI 預覽且完整 build 通過。正式 Google Cloud 專案已啟用 Cloud Translation API，專用且僅限 Translation API 的 Key 已建立並寫入 Supabase Edge Secret；另已在 Google Cloud Console 套用 Translation API 硬性 Quota 保護：general model 14,000 字元／日、15,000 字元／分鐘，以及 v2 60 requests／分鐘。V3.9.13 主 migration 與外鍵索引補充 migration 已套用，`travel-route` v16 已部署。正式 App 授權 smoke 已確認 Wikidata 與 Google NMT fallback 均可寫入快取。尚未升版、部署 GitHub Pages、合併 main、建立 tag 或正式發布。
>
> 前置版本：V3.9.12 已發布，且 Product Owner 已通過真實 Wikimedia 三階段搜尋與外部連結返回 Day 保留補驗。

## 1. 問題與目標

V3.9.12 第 2 階段目前只讀取分類關聯 Wikidata 的既有 `zh-hant`／`zh` 標籤。沒有 Wikidata 項目或繁中標籤的 Commons 分類只顯示原文，並未實際翻譯。

此外，廣泛搜尋與類別內照片目前直接把 Commons 原始 continuation 交給前端。continuation 代表原始媒體清單可能尚有資料，不代表後面一定存在通過授權、格式、尺寸與 attribution 檢查的候選。因此會在零候選、最終少量候選，或下一批沒有新合規照片時仍顯示「載入下一批 24 張」。

本版目標：

- 讓分類提供繁體中文判讀，但絕不以翻譯文字取代 Commons 原始分類或改變第 3 階段查詢。
- 讓「載入下一批」只在後端已確認尚有未展示的合規候選時出現；不因無效 continuation 消耗使用者搜尋動作。
- 修正新設備同時遇到新版 PWA 與遠端行程資料修訂時，版本更新誤報網路失敗、後續資料重新載入卻意外套用新版的競態。
- 維持三階段人工選圖、既有授權安全線與既有 UI 排列；不恢復 AI 候選詞、固定別名擴充、自動評分或自動類別選擇。

## 2. 分類中文判讀

### 2.1 顯示與判讀規則

1. Commons 原始分類名稱為 canonical value，永遠保留且是進入類別照片查詢的唯一參數。
2. 有 Wikidata `zh-hant` 或 `zh` 標籤時優先顯示該標籤。
3. 沒有中文標籤時，顯示 Google Cloud Translation Basic API v2 翻成的 `zh-TW` 輔助文字。
4. 中文翻譯僅協助管理者判讀。翻譯失敗、逾時或無結果時，原文分類仍可立即選擇；不得阻擋第 3 階段。
5. UI 維持現有分類按鈕排列：原文在第一行、中文判讀在第二行。實作前需提供該畫面預覽；若翻譯尚在取得，僅在現有說明區顯示簡短載入狀態，不新增另一套版面。

### 2.2 翻譯提供者與憑證

- 採用 Google Cloud Translation **Basic API v2**，目標 `zh-TW`；以 API Key 呼叫，不採服務帳號或前端 Key。
- 使用一把專用的 Google Cloud API Key，只啟用／限制為 Cloud Translation API。Key 名稱建議為 `GOOGLE_CLOUD_TRANSLATE_API_KEY`；不得以 `SUPABASE_` 開頭。
- Key 只設定為 Supabase Edge Function Secret，由 `travel-route` 在伺服器端讀取；不得提交至 Git、放入 Vite 環境變數、回傳給瀏覽器或寫入資料庫。
- 使用者的登入 Email 只供 Supabase Auth 與既有 Trip 授權判斷，絕不傳送給翻譯服務，也不構成 Google 服務帳號。
- 若 Key 外洩、配額異常或需要撤銷，先在 Google Cloud 停用／輪替，再更新 Supabase Secret；翻譯功能失效不得影響既有選圖。

### 2.3 快取、成本與防濫用

- 新增非公開快取表，至少包含原始分類名稱、目標語系、中文文字、來源（`wikidata` 或 `google-nmt`）、成功時間、到期時間與更新時間。
- RLS 必須啟用，`anon`／`authenticated` 不得有直接讀寫 policy；只有既有、已驗證且通過 Trip 權限檢查的 Edge Function 能以服務端權限讀寫。
- 先讀 Wikidata 與快取，只將未命中的公開分類名稱送至翻譯 API；同一分類的成功翻譯可跨使用者共用。
- 增加短期使用者／批次限額與過期清理，避免任意連續開啟檔案分類成為文字翻譯代理。限額事件只保存最小的使用者識別、時間窗與計數，不保存行程內容或翻譯正文。
- 快取成功值；翻譯失敗僅短暫退避，不得長期快取成「無中文」，避免供應商短暫故障永久遮蔽翻譯。

## 3. 候選批次契約

### 3.1 後端組裝

廣泛搜尋與類別照片共用「可展示候選批次」規則：

1. Edge Function 從 Commons 原始清單依既有順序讀取，套用既有圖片格式、授權、來源與尺寸檢查，並排除已展示檔案。
2. 後端持續讀取必要的原始頁面，直到湊足 24 張合規候選或確認 Commons 已到底；不得把尚未檢查的原始 continuation 當成可展示下一批。
3. 若讀到超過 24 張，使用短效伺服器端批次 session 暫存未展示候選與原始 cursor，避免漏掉、重複或要求瀏覽器保存大型 continuation。
4. 回應中的下一批 token 是不透明的短效 batch token，不再直接暴露 Commons `gsroffset`／`cmcontinue`；token 綁定登入使用者、Trip、搜尋來源與有效期限。
5. 回傳下一批 token 前，後端必須已確認 session 有至少一張未展示合規候選；否則回傳 `null` 並標記到底。

### 3.2 前端顯示規則

| 目前可展示結果 | 是否顯示「載入下一批」 | 說明 |
|---|---:|---|
| 0 張 | 否 | 顯示「目前沒有可用照片」，不誘導額外搜尋。 |
| 1～23 張且已到底 | 否 | 顯示所有結果；這是最終批次。 |
| 24 張且無未展示合規候選 | 否 | 只可在 4 頁內瀏覽，不提供無效續載。 |
| 24 張且已確認仍有候選 | 是，但僅在第 4 頁 | 使用者先看完本批 4 頁，再自行要求載入下一批。 |
| 最後一批少於 24 張 | 否 | 不論剩下 1 張或 23 張，均明確視為底端。 |

- 進入下一批後回到該批第 1 頁；已載入批次不重複混入，已選照片仍保留直到使用者改選、關閉或重新搜尋。
- 類別內照片依 Commons 原始排序；廣泛搜尋依 Commons 搜尋回傳排序。兩者皆僅移除不合規項目與重複項目，不重新評分或重排。
- 原始來源暫時失敗時顯示可重試錯誤；只有明確到底才顯示「沒有更多照片」，不可把逾時、rate limit 或翻譯失敗誤報為到底。

## 4. PWA 更新與遠端行程修訂競態

### 4.1 已確認的現象與原因

在新設備的舊版 App 偵測到新版 metadata，同時遠端行程資料也有修訂時，使用者按「馬上更新」可能看到「請確認網路」或同義錯誤，重試仍失敗；選擇稍後更新後，行程資料提示的重新載入卻可能直接進入新版。

目前 `useAppUpdate` 將下載未完成、Service Worker 尚未接管、更新處理器未就緒與實際網路錯誤集中顯示為同一網路訊息。另一方面，`useTripDataRevision` 的資料提示可直接呼叫 `window.location.reload()`。若先前的 Service Worker 已在背景準備完成，該資料重新載入會成為新版接管的觸發點，造成使用者以為資料更新改變了版本。

遠端資料修訂本身不是已證實的版本更新失敗原因；它是暴露 PWA 接管狀態未被正確呈現的重新載入路徑。

### 4.2 修正契約

1. `useAppUpdate` 必須分別呈現：實際離線／metadata 讀取失敗、新版下載中、等待 Service Worker 接管、已接管可重新載入，以及不可恢復的更新失敗。不得把所有例外都稱為網路錯誤。
2. 當使用者已開始「馬上更新」流程時，App 更新狀態優先於遠端行程修訂提示；資料修訂可被記錄為待處理，但不得在更新接管期間顯示會呼叫重新載入的對話框。
3. 若新版已下載但接管確認超時，提示應說明「新版已準備完成，請重新載入套用」；不得提供會重複同一等待流程的誤導性網路重試。
4. 使用者選擇「稍後更新」時，行程資料的重新載入仍可用，但若該重新載入會套用已準備好的新版，按鈕文案或提示須先清楚告知；不可無提示地把資料重新載入當成版本更新完成。
5. 更新成功後才寫入已更新版本紀錄並重載；失敗或取消時保留可理解的恢復入口，不因資料提示覆蓋或消失。

### 4.3 回歸案例

- 新設備、舊 Service Worker、正式 metadata 已升版、沒有遠端資料修訂：第一次更新可明確顯示下載／接管與結果。
- 同時有新版與遠端資料修訂：更新進行期間不顯示資料重新載入提示；更新完成後才檢查並顯示資料狀態。
- 新版已下載但接管等待超時：不誤報網路錯誤，使用者可透過明確重新載入完成更新。
- 使用者選擇稍後更新後遇到遠端資料修訂：重新載入前明示其會套用已準備的新版本；完成後仍能正確載入最新 Trip。
- 真正離線、metadata HTTP 失敗、Service Worker 下載失敗與控制權未改變：各自有正確文案，且不寫入成功版本紀錄。

## 5. 預計資料與 API 變更

- migration 建立私有翻譯快取、短效批次 session 與最小限額資料；不得回寫 V3.9.12 已發布 migration。
- `commonsPhotoSearch` 與 `commonsCategoryPhotos` 改接收／回傳不透明 batch token 與 `hasMoreEligibleCandidates`，移除前端以 Commons continuation 決定按鈕的邏輯。
- 分類翻譯由受既有 Trip 權限保護的 Edge action 執行；輸入只能來自 Commons 實際讀回的檔案分類，不能讓瀏覽器提交任意待翻文字。
- 前端型別需區分 `canonicalName`、`displayChineseLabel`、翻譯狀態與 `nextBatchToken`；不將翻譯文字寫入 itinerary 或照片 attribution metadata。

## 6. 驗證與發布閘門

1. **UI 預覽核准**：第 2 階段原文／中文兩行與第 1、3 階段第 4 頁的下一批按鈕位置；不核准不實作 App UI。
2. **本機／loopback**：驗證 Wikidata 命中、快取命中、翻譯命中、翻譯失敗 fallback、Key 不出現在 bundle 或日誌、RLS／授權與 rate-limit 邊界。
3. **候選批次 fixture**：零張、3 張到底、24 張到底、25 張、48 張以上、後續原始頁全不合規、重複檔案、來源逾時；廣泛與類別流程各自覆蓋。
4. **PWA 更新回歸**：舊 Service Worker、新設備初始載入、遠端資料修訂與更新同時抵達、接管逾時、真正離線與使用者選擇稍後更新；不得用單純頁面重新載入掩蓋更新失敗。
5. **正式前置**：確認 Google Cloud API 啟用、Key 僅有 Translation API 限制、Supabase Secret 已設定且沒有寫入 repo；migration dry-run、完整 build 與 Edge Function 部署前檢查。
6. **單次正式驗證**：經另行授權後，以正式登入驗證中英日分類的中文判讀、快取後延遲、零／少量／多批候選、PWA／資料修訂競態與外部連結返回 Day 保留。

## 7. 非範圍與版本政策

- 不使用 Gemini 或其他 LLM 產生候選搜尋詞，不恢復 AI 候選詞 UI、固定別名擴充、自動精準評分或自動選類別。
- 不新增一般使用者可管理翻譯、可輸入任意文字翻譯或可見 API Key 的功能。
- 本版為已發布功能的 PATCH 修正，預設 `forceUpdate: false`；只有實作時發現資料相容性、安全或舊客戶端會產生不可接受寫入風險，才另提必要更新建議。
