# V3.8.2 跨日複製時間設定規格

- 狀態：已於 2026-09-11 完成實作、驗證、正式發布與 GitHub Pages 部署
- 排程版本：V3.8.2
- 發布政策：一般更新；發布日期 `2026-09-11`、`minimumSupportedVersion: 3.8.1`、`forceUpdate: false`
- 資料庫：不需要 Supabase schema migration

## 1. 目標

- 避免跨日複製沿用空白時間，導致副本落到目標 Day 最下方。
- 使用者送出前必須主動決定副本的抵達及離開時間，使副本能立即依新抵達時間插入。
- 維持 V3.8.0 的多日一次複製、一次 Trip 寫入、獨立卡片 ID 與路線快取失效規則。

## 2. 已確認介面

- 沿用「跨日複製」對話框，資訊順序為來源卡片、來源時間參考、新時間、目標 Day、操作按鈕。
- 顯示來源卡片的原抵達／離開時間作為純文字參考，不自動填入欄位，也不提供一鍵套用。
- 「抵達時間」與「離開時間」開啟時皆為空白且必填；多個目標 Day 共用同一組時間。
- 空白、格式錯誤或離開早於抵達時即時顯示欄位警告；所有條件滿足前停用「複製到所選 Day」。
- 時間接受半形或全形冒號，儲存前正規化為 `HH:MM`；不支援跨午夜。
- 成功後留在來源 Day，顯示既有的目標 Day 成功訊息，不自動切換日期。
- 已核准模擬圖位於 `docs/assets/v3.8.2/`。

## 3. 複製與排序行為

- 每個目標 Day 建立獨立新 ID，將副本的 `time` 與 `departureTime` 改為本次輸入值。
- 保留標題、類型、說明、文字顏色、地點、確認地點及 `travelKind`。
- 不複製 `travelModeToNext` 或 `travelToNext`。
- 依新抵達時間插入副本；相同時間放在既有同時段卡片之後。
- 只插入新卡片，不重新排列目標 Day 的其他卡片，避免覆蓋 V3.8.0 人工順序。
- 插入使前一張卡片目的地改變時，清除其 `travelToNext` 並保留交通方式偏好。
- 多個 Day 仍以一次 Trip 寫入完成；衝突或失敗時不得產生部分副本。

## 4. 驗收

- 抵達或離開時間任一空白時，顯示警告且無法送出。
- 無效格式及離開早於抵達時，顯示對應錯誤並聚焦第一個錯誤欄位。
- 單日及多日副本都套用同一組新時間，來源卡片保持不變。
- 驗證較早、相同及較晚時間的插入位置，不改動其他卡片的相對順序。
- 寫入失敗或遠端版本衝突時，所有目標 Day 均維持原狀。
- 通過領域測試、TypeScript、lint、完整 build、桌面及 390×844 手機版面驗證。

## 5. 不在本版範圍

- 每個目標 Day 分別設定時間。
- 依來源停留時間自動計算離開時間。
- 複製後自動進入排序模式、切換目標 Day 或重排整日卡片。
- 跨午夜、全日時間重算或批次路線查詢。
