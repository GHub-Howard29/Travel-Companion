# V3.10.2 天氣更新問題診斷與修正範圍

> 定義日期：2026-10-18
> 狀態：本機驗證完成，待正式發布前核對與部署。

## 判斷結論

目前不能從 APP 畫面直接判定是 Google Places、Open-Meteo、Supabase 快取寫入或授權哪一層失敗，因為 V3.10.1 的 Edge Function 會捕捉刷新例外並只回傳 `unavailable`，前端也只顯示「暫時無法取得天氣」。因此「一直無法更新」的已確認問題是診斷資訊不足；單一上游故障仍屬待證實假設。

## 本次 V3.10.2 範圍

- 使用不含秘密、Token、地點識別值或原始錯誤內容的 trace ID 與安全錯誤碼，區分座標讀取／寫入、Google Places、Open-Meteo、租約與天氣快取階段。
- 前端函式呼叫設定 60 秒逾時；對未回傳、錯誤對應或仍停在 `waiting` 的卡片統一收斂為可見的 unavailable 狀態，避免畫面永久等待。
- 保留既有 Trip 授權、座標／天氣快取、租約、6 小時背景刷新與最多 10 個目標／5 個併發規則。

## 已完成驗證

- 天氣靜態契約檢查通過。
- App 與 Node TypeScript 型別檢查通過。
- 本機 Supabase、`travel-route`／`weather-forecast` Edge Function 與 APP 均可啟動。
- 使用者已確認本機天氣可正常取得；正式環境再次發生時仍需保留診斷碼，以區分上游或快取階段。

## 驗收門檻

正式發布後需以合資格的真實行程卡片確認單卡與跨行程刷新，並保存診斷碼對應的階段與結果；若再次失敗，依診斷碼決定是否需要後續 migration、Edge Function 或前端修正。
