## 版本編號原則

- `MAJOR`：產品世代、核心架構或資料模型有大規模且不相容的變更。
- `MINOR`：新增使用者可感知的主要功能，或進入新的產品功能階段。
- `PATCH`：Bug 修正、小型 UI／體驗改善、效能調整、安全維護或既有功能補強。
- `forceUpdate` 與版本層級分開判斷；資料不相容、安全、RLS／schema、同步或舊快取有重大風險時才建議必要更新。
- 版本發布後不回寫版號、migration 或版本歷史；問題以新版本向前修復。

## 排程中版本

### V3.9.13 Commons 分類中文判讀與候選批次修正（已定案、待實作）

- 補足 V3.9.12 未完整落地的分類中文判讀：優先使用 Wikidata 既有繁中標籤；無標籤時以 Google Cloud Translation Basic API v2 翻成 `zh-TW`。Commons 原始分類名稱永遠是唯一查詢依據，中文只供人工判讀。
- 翻譯 Key 僅存於 Supabase Edge Function Secret，使用專用、僅允許 Cloud Translation API 的 API Key；不使用登入者 Email、不暴露前端、不恢復 AI 候選詞或自動分類流程。
- 修正廣泛搜尋與類別內照片的續載契約：後端先組裝實際可展示的 24 張批次，並且只有已確認仍存在未展示合規照片時才回傳下一批控制資訊。零張、少於 24 張的最終批次、或後續沒有新合規照片時均不顯示「載入下一批」。按鈕只在目前 24 張的最後一頁才出現。
- 修正新設備同時偵測新版 PWA 與遠端行程資料修訂時的更新競態：區分網路、新版下載、等待接管與接管逾時；更新進行中延後資料重新載入提示，避免資料提示的重新載入意外完成版本切換。
- UI 維持既有排列；正式 App 實作前須先提供第 2 階段中文判讀與批次尾頁按鈕的預覽供核准。詳細資料、權限、快取與驗證規格見《[64_V3.9.13_分類翻譯與候選批次修正規格](64_V3.9.13_分類翻譯與候選批次修正規格.md)》。

### V3.9.14 多人帳本即時同步與權限文案修正

- 修正 BUG012：兩個設備同時停留在同一 Trip 帳本頁時，新增／刪除帳目應透過 Supabase Realtime 即時反映；目前 30 秒輪詢備援已正常，必須保留，且不得因修正 Realtime 而退化。
- 檢查 Realtime subscription 的建立／解除生命週期、Trip／帳本過濾條件、事件收到後的重新抓取或本機 state 更新；驗收以兩設備同畫面測試新增與刪除，不以切頁或等待 30 秒視為即時通過。
- 同版修正 BUG033：只有具備共用帳本／代其他成員記帳能力的情境才顯示相關提示；個人帳本與無共用權限使用者不得顯示「已依登入 Email 預設，可代其他成員記帳」。
- 本版限於 Expense／帳本同步與權限文案，不加入照片快取或其他新功能；預設一般更新。

### V3.9.15 行程照片離線預載修正

- 修正 BUG032：使用者在線載入 Trip 後，背景預載該 Trip 目前行程卡片實際使用的照片，使離線後不必曾逐一卡片開啟也能顯示既有照片。
- 預載範圍只包含目前已選用的行程卡片照片，不預載 Commons 搜尋候選、分類候選或尚未選用的圖片。
- 已存在快取不得重複下載；照片更換、Trip 刪除或失效資源需有可控清理策略，避免 Cache Storage／IndexedDB 無限制累積。
- 預載失敗不得阻擋 Trip 文字內容或一般操作；驗收需包含未逐一卡片開啟即離線、重新啟動 PWA、照片更換後離線與多 Trip 儲存空間情境。
- 本版只處理「照片是否可離線取得」；離線冷啟動速度與效能量測仍保留在 V3.10.2。

### V3.10.1 驗證套件整併與建置效能基線

- 建立完整 build 中各驗證群組、TypeScript 與 Vite build 的耗時基線。
- 依領域整併驗證入口與失敗報告，但不縮減 release build 的完整發布驗證。
- V3.9.3 已在 `src/main.tsx`／`src/App.tsx` 建立 `tc_app_bootstrap_start` 與 `tc_app_bootstrap_duration` 總啟動量測；V3.10.1 不重複新增程式內量測埋點，僅量測驗證與建置流程耗時。
- 不包含功能、資料庫、Edge Function、正式環境、版本 metadata 或部署變更。

### V3.10.2 離線冷啟動剖析與定向改善

- 沿用 V3.9.3 既有的總啟動量測，在本機新增 Service Worker／navigation、session、Trip 快取、localStorage、IndexedDB 與首個可操作畫面的分段耗時量測，以找出離線冷啟動約 30 秒的瓶頸。
- 只在證據足夠時實作定向改善；不破壞 Offline First、墓碑、pending 與同步安全。
- 不重複 V3.6.5 的更新後載入改善或 V3.9.3 的冷啟動總埋點；量測資料維持本機 Console，不新增遠端 telemetry 或蒐集行程、帳目、Email 等資料。

### V3.10.3 零費用 Playwright 響應式 E2E 回歸基礎

- 只使用 loopback fixture 與本機瀏覽器／viewport 模擬，不使用 production、外部 API 或付費雲端實機。
- 優先覆蓋核心導覽、窄螢幕溢位、重要對話框與既有合成資料契約。
- 不以模擬取代 Android／iOS 實體裝置的 PWA、OAuth、相機、離線與跨裝置驗證。

### V3.10.4 照片功能模組化、型別邊界與按需載入

- 沿用既有 lazy loading 與 Excel 動態載入成果，不重複開發。
- 以現有照片搜尋、裁切、上傳與來源 metadata 的型別邊界為主，不擴張新圖庫來源。
