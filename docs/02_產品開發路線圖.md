# 一、產品願景

Travel Companion 的目標不是提供單一功能，而是打造一套完整的旅行管理平台。

所有功能皆以 Trip 為核心，逐步擴充各種 Travel Tool，陪伴使用者完成每一次旅行。

---

# 二、V3 核心目標

建立一套：

- 易閱讀
- 易維護
- 易擴充
- 易測試
- 支援長期演進

的產品架構。

# 四、V3 開發階段

## 第一階段：Foundation（共同能力）

目標：

建立所有 Travel Tool 共用能力。

目前規劃：

- Workspace
- Current Trip
- Current User
- Role
- Permission
- Sync State
- Storage Layer

目前已新增 Trip 管理第一版：

- App 內新增 / 編輯旅程基本資料。
- 旅程清單改為 JSON seed + Supabase trips + localStorage fallback 合併。
- `super_admin` 可新增旅程。
- `trip_editor` 可編輯被指派旅程。
- 可編輯者 Email 由 Supabase `admin_users` 管理。
- Trip Cloud schema / validation 已透過 Supabase connector 執行並驗證。

完成後，所有 Travel Tool 共用同一套基礎能力。

## 第二階段：Travel Tool 模組化

逐步完成各功能模組。

目前規劃：

- Expense
- Checklist（已完成共同 / 私人清單的最小雲端同步）
- Reference / Other Info（已完成本機管理與最小雲端同步）

各 Tool 不互相依賴。

目前優先順序：

1. Travel Tool 模組化落地：整理工具入口、工具型別判斷、登入需求、頁首樣式與特殊資訊判斷等共用規則，不改變既有 UI 或使用方式。
2. 帳本功能開發：帳本 UI 改善、記帳日期、日期分頁 / 分組、最新排序與附件管理改善。

## 第三階段：新功能擴充

下一個已核定的 Travel Tool 為 V3.3.0「外幣換算」。它依附於個別 Trip，提供換匯紀錄、加權平均匯率與外幣轉 TWD 的參考換算；第一版不依賴即時匯率 API。

版本控管：V3.3.0 完成並正式發布前，不開啟其他新版本的功能開發。期間所有小修正均歸屬 V3.3.0；發布後才可建立後續版本計畫。

其他新 Travel Tool（例如預約紀錄、行李清單、旅行日誌、保險資訊、AI 助手）仍暫不排程，須在 V3.3.0 發布後由 Product Owner 另行確認。

V3.3.0 發布後的下一個預定版本為 V3.4.0「前端載入效能優化」：針對建置時超過 500 kB 的初始 JavaScript bundle，評估以動態載入降低首次開啟下載量。僅在 V3.3.0 主功能回歸全數通過且沒有已知待改善問題時才開始。

V3.4.0 發布後先進行 V3.4.1「離線狀態、Other Info 本機優先同步與共用帳本 ownership 修正」：以瀏覽器實際連線狀態區分線上、離線與 Supabase session；資訊頁改為本機先存、畫面立即更新、單一最新快照背景同步；共用帳本改採 A+B 聯集、付款人與記錄者分離及離線 queue 依登入者隔離。完整規格請參閱《16_V3.4.1_離線狀態與OtherInfo本機優先同步規格》。

### V3.4.2 離線同步補正與 PWA 啟動動畫（已發布）

- 改善共同清單恢復連線時的同步收斂，避免舊資料覆蓋較新的本機修改。
- 歷史行程在離線狀態下改為完整唯讀，避免產生無法安全同步的操作。
- 每日行程補上到達與離開時間，作為 V3.5.0 地點間預估移動資訊的時間資料基礎。
- 新增可離線使用的 PWA Splash 啟動動畫，初始化完成後自動淡出並進入 App。

### V3.4.3 PWA 啟動畫面載入銜接優化（待發布）

- 在 React 程式完成載入前顯示 HTML 預載 Splash，接續作業系統的 PWA 啟動畫面。
- 縮短系統啟動畫面結束後只有圖示或空白畫面的等待感，再銜接完整 App 啟動動畫。
- 系統 PWA Splash、HTML 預載 Splash 與完整 App 動畫改用相容藍色背景；完整彩色圖示先柔邊融合並淡出，再接續地圖、行李箱、雲朵與無尾煙飛機 CSS 動畫。
- 保持離線可用，並維持既有 PWA 桌面圖示、網站 favicon 與 manifest 圖示不變。
- 程式、文件與本機 `npm run lint`、`npm run build` 驗證已完成；待 Product Owner 手動合併、部署及 Android／iOS 已安裝 PWA 銜接驗證。

V3.4.3 正式發布後，依序進行下列安全修正版本，再啟動 V3.5.0「地點間預估移動資訊」。安全修正採逐項提出方案、由 Product Owner 確認後實作的方式進行，避免同時改動多個權限或資料邊界。

### V3.4.4 開發環境與依賴安全基線

- `.env` 與所有 `.env.*` 環境檔一律排除於 Git，僅保留可提交的 `.env.example`。
- 排除 Supabase CLI 本機狀態目錄 `supabase/.temp/`。
- 固定 Node.js `22.23.2`、npm `10.9.8` 與 Supabase CLI `2.115.0`，其他開發電腦以 `npm ci` 重建相同依賴。
- 使用非強制 `npm audit fix` 修正可安全升級的間接依賴，不使用可能造成 ExcelJS 降版的 `npm audit fix --force`。
- ExcelJS 間接依賴 `uuid` 的剩餘中風險漏洞目前沒有可觸發的使用路徑，暫時接受並持續追蹤官方更新。

### V3.4.5 Trip 公開／私人與 Guest 存取

- Supabase `trips` 新增公開狀態欄位，新 Trip 預設不公開。
- Trip 管理介面提供公開／不公開設定，只有 `super_admin` 可變更公開狀態。
- Guest 僅能讀取公開 Trip；`trip_editor` 可讀取自己負責的私人 Trip；`super_admin` 可讀取全部 Trip。
- 以 Supabase RLS（資料列權限，用來限制誰能讀取特定 Trip）阻止直接 API 越權，不只依賴前端隱藏。
- 不公開 Trip 移出 `public/trips/`，避免部署後仍可透過靜態網址下載。
- 登入後將有權限的私人 Trip 安全快取至本機，保留 Offline First；公開狀態切換時處理既有快取。

### V3.4.6 Supabase Storage 附件權限

- 將 `expense-attachments` bucket 與 `storage.objects` 權限政策納入可版本控制的 migration。
- 確認附件 bucket 為 private，並依 Trip 權限限制上傳、讀取、更新與刪除。
- 驗證附件路徑中的 Trip ID，阻止使用者猜測或存取其他 Trip 的附件。
- 配合附件覆蓋上傳需求，完整驗證 INSERT、SELECT、UPDATE 權限。
- 評估目前七天簽名網址的有效期限是否需要縮短。

### V3.4.7 Supabase 資料庫權限函式硬化

- 盤點 `SECURITY DEFINER` 函式，固定安全的 `search_path`，移除不必要的公開執行權限。
- 確認 `public` schema 不允許不可信角色建立可被權限函式誤用的物件。
- 執行 Supabase database advisors，回歸 Trip、Checklist、Other Info、Expense 與 Exchange Rate 權限。

### V3.4.8 前端瀏覽器安全防護

- 加入 Content Security Policy，限制腳本、圖片與 API 連線來源。
- 檢查 `target="_blank"`、`window.open`、`innerHTML` 與使用者輸入網址的安全邊界。
- 評估 Referrer Policy、Permissions Policy 與 GitHub Pages 可提供的安全 Header。
- 回歸 Google OAuth、PWA、Service Worker、圖片附件與 Excel 匯出。

### V3.5.0 地點間預估移動資訊

V3.4.4～V3.4.8 安全修正完成後，啟動 V3.5.0「地點間預估移動資訊」：於每日行程相鄰地點卡片之間顯示交通方式、預估時間與距離，支援開車、步行及大眾運輸；由 Trip Editor / Admin 查詢並儲存，Guest / User 僅查看快取結果。完整決策與成本控制規格請參閱《15_V3.5.0_地點間預估移動資訊規格》。

# 六、Checklist 規劃

目前規劃：

- Public Checklist
- Private Checklist

兩者皆依附於 Trip。

目前已完成：

- 共同檢查清單最小雲端同步。
- 私人確認清單最小雲端同步。
- `guest` / `user` 查看共同清單時顯示乾淨未勾選版本，作為自己的準備對照。
- `trip_editor` / `super_admin` 可同步共同清單勾選狀態。

目前同步策略：

- 共同項目 App 內新增 / 編輯 / 刪除已完成第一版。
- 共同清單已具備本機 `localStorage` 持久化與 Supabase 最小雲端同步。
- 暫不規劃 Pending Queue（離線或同步失敗時暫存待上傳操作的佇列）。
- 暫不規劃複雜 Conflict Resolution（本機與雲端同一筆旅行資料都被修改時的合併或取捨規則）；若多人同時修改，以最後成功上傳到 Supabase 的資料為準。

下一步建議：

Checklist 與 Reference / Other Info 先視為 V3-1 最小同步完成；若後續有 BUG 回報或 Product Owner 提出待改善功能計畫，再安排同步行為補強。

近期 UI 補強：

- 共同檢查清單與私人確認清單已改為瀏覽優先，透過「管理」進入新增、編輯、刪除層。
- 領隊導遊聯絡資訊 / 自駕租車須知與其他資訊已採同一個「管理 / 退出」模式，避免管理員日常瀏覽時誤觸。
- 旅費記帳本已補上既有附件單獨移除功能，附件移除不會刪除帳目資料。
- 旅費記帳本新增與編輯附件入口已改為「拍照」與「相簿」兩個明確入口，避免不同手機瀏覽器只顯示單一路徑。

# 七、Reference 規劃

Reference 提供：

旅行資訊整理。

例如：

- 地址
- 網站
- 注意事項
- 行前資訊

預設資料由 seed data 提供。

V3-1 允許使用者在 APP 內做簡易本機管理。

V3-1 第一階段已完成：

- Trip sidebarConfig 接入「其他資訊」
- OtherInfoPage 簡易管理 UI
- Folder chips 與資料筆數
- 自由行 / 跟團第一批 seed data
- seed data + localStorage 合併讀取
- 新增、編輯、刪除 item
- 編輯 seed item 時以 localStorage 覆蓋
- 刪除 seed item 時以 `isDeleted` 標記覆蓋
- `http` / `https` URL 自動轉為可點擊超連結
- Other Info Supabase schema / RLS 已執行並驗證。
- 前端最小雲端同步已完成，支援讀取、upsert、軟刪除與 Trip 刪除清理。

目前不列為待開發：

- 多人即時協作。
- 複雜衝突合併。

若有回報 BUG 或提出待改善功能計畫，再針對 Other Info 雲端同步行為安排修改。

未來可持續擴充。

# 八、權限規劃

目前規劃：

- 未登入使用者
- 一般登入使用者
- Trip Editor
- Super Admin

所有權限皆由 Foundation 管理。

目前 Trip 管理權限：

- Guest：可瀏覽旅程。
- 一般登入使用者：可使用個人功能，但不可新增 / 編輯共享旅程。
- Trip Editor：可編輯被指派旅程內容，不可管理可編輯者 Email。
- Super Admin：可新增旅程、編輯所有旅程、管理可編輯者 Email。

# 九、同步規劃

- Download

# 十三、開發原則

每新增一個功能：

應優先建立新的 Travel Tool。

避免修改既有 Tool。

若需大量修改既有程式，應重新評估架構是否合理。
