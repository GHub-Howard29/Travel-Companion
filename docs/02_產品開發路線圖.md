## 版本編號原則

- `MAJOR`：產品世代、核心架構或資料模型有大規模且不相容的變更。
- `MINOR`：新增使用者可感知的主要功能，或進入新的產品功能階段。
- `PATCH`：Bug 修正、小型 UI／體驗改善、效能調整、安全維護或既有功能補強。
- `forceUpdate` 與版本層級分開判斷；資料不相容、安全、RLS／schema、同步或舊快取有重大風險時才建議必要更新。
- 版本發布後不回寫版號、migration 或版本歷史；問題以新版本向前修復。

### V3.9.22 排序後續時間重算與調整時間整合

- 原 V3.9.21 計畫因插入 PWA 更新載入修復而順延為 V3.9.22；既有產品規則與主要 UI 流程維持不變。V3.9.22 RC 另須以 V3.9.21 正式版作為舊客戶端，補驗新版 PWA 更新流程的接管、按鈕鎖定與 reload 不白畫面。
- 排序與時間重算分離：儲存順序只寫入新順序，原時間保持不變；之後由使用者按「預覽新時間」才計算。
- 新時間預覽採 30 分鐘向後進位，顯示原時間／新時間／必要交通時間，允許逐項接受或手動延後到達時間；只有最後按「套用新時間」才一次寫回正式 Trip。
- 不開發永久性的固定時間活動功能；少數精確時間需求由預覽階段人工調整處理。
- 「餐飲」與「其他」卡片才顯示「納入交通計算」：餐飲預設勾選、其他預設不勾選；其餘類型預設都參與交通計算。被略過卡片不切斷交通鏈，系統跨過它計算前後最近有效節點。
- 已套用時間後若原本略過的卡片新增地點或改為參與交通計算，只標記受影響區段並提供「預覽更新」，不得自動改寫既有路線與時間。
- 優先沿用有效路線快取，只查詢必要的新相鄰路線；缺資料、離線、API 失敗、航班與跨午夜均依規格採停止／略過策略，不猜測交通時間、不部分套用。
- 既有「調整時間」入口保留，與排序後預覽共用同一套底層時間預覽能力，不開發兩套引擎。完整規格見《[68_V3.9.22_排序後續時間重算評估紀錄](archive/v3.9.13-v3.9.29/68_V3.9.22_%E6%8E%92%E5%BA%8F%E5%BE%8C%E7%BA%8C%E6%99%82%E9%96%93%E9%87%8D%E7%AE%97%E8%A9%95%E4%BC%B0%E7%B4%80%E9%8C%84.md)》。

### 未排定版本：AI 每日行程卡片 Excel 匯入

- 產品主要範圍、整趟覆蓋及嚴格雲端保護已記錄於規格草案，但**尚未安排版本號，也未納入任何已排程版本**。
