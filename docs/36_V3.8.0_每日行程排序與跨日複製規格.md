# V3.8.0 每日行程排序與跨日複製規格

- 狀態：已發布；2026-09-10 完成 `main` 合併、帶註解標籤 `v3.8.0`、GitHub Pages、正式 metadata 與前端資產驗證
- 排程版本：V3.8.0
- 發布政策：必要更新；發布日期 `2026-09-10`、`minimumSupportedVersion: 3.8.0`、`forceUpdate: true`
- 資料庫：不新增 Supabase schema 或 migration

## 1. 目標

- 讓管理者快速調整單一 Day 的卡片順序。
- 讓同一張行程卡片可重複利用於同一旅程的多個其他 Day。
- 優先重用既有 V3.7.0 時間調整功能，避免在排序模式重建第二套全日路線與時間計算流程。

## 2. 資料與相容性

- `ItineraryItem` 新增可選的穩定 `id`；新建與複製卡片立即建立 ID，舊卡片在首次排序或其他行程寫入時補齊。
- `daysData[day]` 的陣列位置是唯一正式順序，不新增 `sortOrder` 或第二套排序來源。
- 舊資料尚未持有 ID 時，畫面使用當次載入的暫時識別；儲存後改用正式 ID。
- V3.8.0 新版不再於顯示時強制依到達時間排序。新增與複製卡片仍依時間插入；編輯既有卡片時間不自行移動位置。
- 因舊版仍可能依時間重新排序並寫回陣列，本版已確認將最低支援版本提升至 3.8.0。

## 3. 調整順序

- 入口位於 Day 行程管理區，名稱為「調整順序」。進入後停用新增、編輯、刪除、複製及調整時間。
- 支援拖曳、鍵盤排序及卡片上的上移／下移按鈕；拖曳需使用既有 `@dnd-kit` 與 `SortableCard` 能力。
- 所有變更先存在元件草稿；「取消」還原原順序，「儲存順序」才執行一次 Trip 寫入。
- 儲存時保留每張卡片原到達與離開時間，不進行路線查詢或全日時間重算。
- 比較調整前後相鄰目的地；目的地改變的來源卡片清除 `travelToNext`，但保留 `travelModeToNext` 作為偏好。
- 新順序若與原時間不一致，沿用既有衝突與路線待更新提示，不阻止儲存。
- 儲存成功後顯示簡短結果，提供「接著調整時間」按鈕進入既有 V3.7.0 模式；使用者亦可直接完成。
- 遠端版本已變更或儲存失敗時，保留排序草稿並顯示錯誤，不做部分更新。

## 4. 跨日複製

- 管理模式下每張卡片提供「複製」；開啟視窗後可複選同一旅程內除來源 Day 以外的一個或多個 Day。
- 目標清單顯示 Day、日期與目前卡片數；至少選一個 Day 才能送出，允許使用者重複複製相同卡片。
- 每個目標 Day 建立獨立新 ID，保留時間、標題、類型、說明、文字顏色、地點、確認地點與 `travelKind`。
- 不複製 `travelModeToNext` 或 `travelToNext`，因兩者描述來源 Day 的下一段交通關係。
- 副本依到達時間插入；相同時間放在既有同時段卡片之後，無有效時間時放在最後。
- 插入點前一張卡片若因此改變目的地，清除其 `travelToNext` 並保留原交通方式偏好。
- 多個 Day 的變更以一次 Trip 寫入完成；任一遠端衝突或寫入錯誤時全部維持原狀。
- 成功後在原 Day 顯示已複製到哪些 Day；不自動切換日期，也不主動產生多日路線 API 查詢。

## 5. 不在 V3.8.0 的範圍

- 排序後自動重算全日到達／離開時間。
- 排序時批次查詢所有新路線、處理跨午夜或建立成功／失敗雙軌時間預覽。
- 跨旅程複製、多張卡片批次複製、拖曳跨 Day，或目的地重複偵測。
- 卡片照片、使用紀錄、資料庫 schema／RLS 變更。

## 6. 驗收

- 舊卡片無 ID、相同時間、空白時間及重複標題時仍可穩定排序並補齊唯一 ID。
- 滑鼠、觸控、鍵盤及上／下按鈕皆可調整；取消不寫入，儲存後重新載入仍維持順序。
- 只清除目的地改變的路線快取，未改變的有效路線保持不變。
- 複製到單日／多日、同時間／無時間插入、新 ID、欄位保留及路線欄位排除皆符合規格。
- Guest、User、無權限帳號、離線與不允許編輯的歷史行程不能進入寫入流程。
- 跨裝置版本衝突不覆蓋遠端，也不產生部分 Day 更新。
- 通過專項純函式測試、TypeScript、lint、完整 build，以及桌面與手機版面驗證。
