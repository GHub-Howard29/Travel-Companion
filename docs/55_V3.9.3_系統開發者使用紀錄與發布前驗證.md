# V3.9.3 系統開發者、使用紀錄與正式發布紀錄

> 狀態：已正式發布；production migration、Git 與 GitHub Pages 部署完成
>
> 發布日期：2026-09-18
>
> 版本政策：一般更新；`minimumSupportedVersion: 3.9.2`、`forceUpdate: false`

## 1. 本版範圍

- 建立唯一啟用中的系統開發者 capability；以 Auth `user_id` 為主、正規化 Email 為一致性檢查。
- 保存最小彙總：Email、首次使用、最近使用、30 分鐘窗口的有效工作階段數；不保存 IP、裝置、位置、語系、頁面或行程內容。
- 側邊欄在版本資訊上方顯示「使用紀錄／進入時驗證」；只有 capability 驗證成功的帳戶可見。
- 彙總 RPC 再次執行後端授權；前端隱藏不是安全邊界。失敗採 fail closed，紀錄失敗不阻擋 App 啟動。
- 整合 V3.9.1 的 17 個驗證入口為 `npm run verify:v391:all`，舊版重型專項留在完整回歸；一般 build 新增 App TypeScript 與 V3.9.3 專項檢查。
- 以 `tc_app_bootstrap_start` 與 `tc_app_bootstrap_duration` 建立啟動量測基線；本版不改資料載入策略。

## 2. 資料庫與授權

Migration：`20260917121757_v393_system_developer_and_usage.sql`。

- `private.system_developers`：最多一筆 `is_active = true`，前端與 Data API 無直接表權限。
- `private.user_usage_summaries`：每位 Auth 使用者一筆彙總，30 分鐘內重複啟動只更新最近時間、不增加有效工作階段。
- `public.tc_is_system_developer()`、`public.tc_record_usage_session()`、`public.tc_get_usage_summary()`：`SECURITY INVOKER`，只授權 `authenticated`。
- 高權限實作位於非暴露的 `private` schema，採 `SECURITY DEFINER` 並固定空 `search_path`；anon 無執行權。
- capability 不增加任何 Trip、帳本、附件、私人清單或其他既有資料權限。

## 3. 發布前驗證結果

- `npm run lint`：通過。
- `npm run build`：通過；包含版本政策、production origin、17 項 V3.9.1、V3.9.3 專項、App／Node TypeScript、PWA 與全產物 loopback 掃描。
- 本機 Supabase migration：由空白以外的既有本機資料向前套用成功，未執行 `db reset`。
- 資料庫 postflight：兩張 private 表 RLS 開啟，anon／authenticated 無表讀權；public RPC 為 invoker，private core 為固定空 `search_path` 的 definer；grant 符合預期。
