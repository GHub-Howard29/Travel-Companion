# 功能規格

> Version：V3.0

---

# 一、目的

本文件定義 Travel Companion V3 各旅行工具（Travel Tool）的產品功能規格。

每個旅行工具均依附於 Trip（旅程）之下，並遵循統一的設計規格。

本文件描述的是產品功能與規格，不負責記錄開發進度；開發版本與完成狀態請參閱《02_產品開發路線圖》。

---

# 二、旅行工具定義

旅行工具（Travel Tool）係指依附於 Trip（旅程）之下，提供單一產品功能的功能模組。

目前已規劃的旅行工具：

- 旅程資訊
- 記帳本
- 共同清單
- 私人確認清單
- 其他資訊

未來將依產品需求持續新增新的旅行工具。

---

# 三、Trip 架構

```text
Trip（旅程）
│
├── 旅程資訊
│
├── 記帳本
│
├── 共同清單
│
├── 私人確認清單
│
└── 其他資訊
```

所有旅行工具皆依附於 Trip。

---

# 四、旅行工具共通規格

所有旅行工具均須定義以下內容：

| 項目 | 說明 |
|------|------|
| 功能說明 | 此旅行工具的主要用途。 |
| 儲存位置 | localStorage、IndexedDB、Supabase 等。 |
| 資料擁有者 | Trip 或個人。 |
| 適用對象 | 哪些使用者可使用此旅行工具。 |
| 權限規則 | Viewer、Editor、Admin 等權限規則。 |
| 是否可編輯 | 是否允許修改內容。 |
| 同步方式 | 不同步、本機同步、雲端同步等。 |
| 生命週期 | 建立、保存與刪除時機。 |

# 五、旅程資訊

## 功能說明

管理旅程本身的基本資訊。

## 旅行工具規格

| 項目 | 內容 |
|------|------|
| 儲存位置 | Supabase |
| 資料擁有者 | Trip |
| 適用對象 | Trip 成員 |
| 權限規則 | 依 Trip 權限管理 |
| 是否可編輯 | 目前僅建立旅程時建立，後續依功能規劃調整 |
| 同步方式 | 雲端同步 |
| 生命週期 | 建立 Trip 時建立，刪除 Trip 時一併刪除 |

## 管理資料

- Trip
- Trip Member
- Itinerary（未來）

## 功能能力

### 基本資料

- 旅程名稱
- 日期
- 地點

### 成員管理

- 共用旅程
- 管理旅程成員

### 行程管理

- 每日行程
- 行程排序
- 行程時間

### V3.6.0 地點間預估移動資訊（程式與部署前文件完成，尚未整合測試／部署）

- 兩張直接相鄰且都有已確認地點的卡片之間可顯示交通方式、預估時間與距離。
- 每段獨立設定，預設開車，支援開車、步行及大眾運輸。
- 無地點卡片中斷交通關聯，不跨卡計算。
- 排除機場到機場的航班時間與距離。
- Guest / User 只查看快取結果；Trip Editor / Admin 才能查詢及儲存。
- 完整需求、權限、成本與不做範圍請參閱《15_V3.6.0_地點間預估移動資訊規格》；測試與發布順序請參閱《21_V3.6.0_發布前測試與正式發布流程》。

### V3.6.2 行程天數變動防護與歷史行程鎖定（已手動發布及部署）

- 增加天數時建立新的空白 Day；縮短天數時，必須先顯示所有尾端受影響 Day 的卡片與路線數量，取得二次確認後才永久刪除。
- 縮短可一次移除任意 N 天，不限最後一天；取消確認時不得儲存表單或刪除任何資料。
- 行程最後一天後的翌日 `00:00` 起，依台灣時間將 `trip_editor` 的歷史行程共用資料全部改為唯讀；`super_admin` 仍可管理，介面角色文案顯示「管理者」。
- 直接刪除、N 天影響摘要及二次確認只適用天數變動；其他編輯與刪除整個行程不新增本次確認，並依非歷史／歷史角色規則執行。
- 本版採必要更新；正式版本已將 `minimumSupportedVersion` 提高至 `3.6.2`，並以 `forceUpdate: true` 相容不認識最低支援版本欄位的舊 App。Git 版本標籤為 `v3.6.2`，發布狀態為「已發布」。
- 詳細文案、資料邊界與驗收矩陣見《24_V3.6.2_行程天數縮短刪除與歷史行程鎖定規格》。

### V3.6.3 V3.6.2 發布後前端修正（待開發）

- V3.6.2 縮短天數、歷史角色、離線／同步及桌面／Android 裝置矩陣已通過；iOS Safari／standalone PWA 保留補驗證。
- 已確定納入 BUG029：更新後版本資訊不得沿用「客戶端目前是否仍需更新」的即時判定，應顯示該版本保存的必要／一般更新政策。
- 更新提示的阻擋邏輯與版本紀錄的發布政策顯示必須分離，並補齊升級前、升級後與歷史版本案例。
- 同版修正交通方式圖示、管理者歷史提醒時機，以及縮短天數兩階段不同文案確認。
- 歷史唯讀參與者與跨裝置 Trip 資料變動提醒已拆至 V3.6.4；除本版必要 UI 外不調整既有畫面。
- 更新政策待最終修正風險確認。完整規格見《25_V3.6.3_V3.6.2發布後前端修正規格》。

### V3.6.4 歷史唯讀參與者與跨裝置資料變動提醒（待開發前確認）

- 「歷史唯讀參與者」是目前 Trip 的有效存取狀態，不是 User，也不變更 `admin_users` 角色；須保留完整歷史共用資料讀取能力、取消編輯者專用鎖定提醒並禁止所有共用資料寫入。
- 同一帳號在其他受指派的非歷史 Trip 仍保留 `trip_editor` 權限；非參與者的歷史 `trip_editor` 與管理者規則不變。
- 跨裝置資料變動只顯示手動刷新提醒，不自動重載或捨棄編輯中資料；刷新後使用 RLS-safe query 重新取得資料。
- 資料變動提醒的事件範圍、介面、未儲存判定、離線備援、Realtime／Broadcast、安全、migration、相容與更新政策，須在開發前再次討論及核准。
- 完整規格見《26_V3.6.4_歷史唯讀參與者與跨裝置資料變動提醒規格》。

# 六、記帳本

## 功能說明

管理旅程內所有收支資料及附件。

## 旅行工具規格

| 項目 | 內容 |
|------|------|
| 儲存位置 | IndexedDB／Supabase（依權限） |
| 資料擁有者 | Trip（一般 User 使用本機資料） |
| 適用對象 | Admin、Editor、User |
| 權限規則 | 依 Trip 權限管理 |
| 是否可編輯 | 可（依權限） |
| 同步方式 | Offline First，依權限同步 |
| 生命週期 | 建立 Trip 後即可使用，刪除 Trip 時依規則移除 |

## 管理資料

- Expense
- Attachment

## 功能能力

### 帳務管理

- 新增帳目
- 修改帳目
- 刪除帳目
- 修改記帳日期
- 日期排序
- 日期分頁
- 多幣別：目前支援 TWD、JPY、KRW、USD、EUR
- 付款人
- 若旅程設定 `participantEmailMap`，系統依登入 Email 預設對應參與者，但付款人可改選其他旅程成員，支援代記帳。
- 新增 / 編輯旅程時以 `名稱=Email` 維護參與者與登入 Email；名稱作為帳本付款人顯示，Email 用於預設付款人與辨識實際記錄者。
- 共用帳目分開保存 `payer` 與 `owner_user_id`／`recorded_by_email`；前者用於分帳，後者用於同步與修改／刪除權限。
- 共用帳本以 `trip_id + client_item_id` 疊加多人資料，不採最後登入帳號覆蓋整份帳本。
- 分攤結算需先計算每位成員實際應分攤金額，再用已墊金額扣除應分攤金額，確保應收與應補總額一致。
- TWD / JPY / KRW 採整數分攤；若平均後有小數，應分攤者無條件進位負擔，代墊者承接零頭盈餘。
- USD / EUR 以分為最小單位結算。

### 附件管理

- 新增附件
- 修改附件
- 刪除附件
- 開啟附件
- 自動更新附件連結
- 新增 / 編輯時提供「拍照」與「相簿」兩個明確入口
- 附件同步失敗後可重試，重試時需保留本機附件暫存

目前已完成補強：

- 編輯既有帳目時，若該帳目已有附件，已提供「移除附件」功能，且刪除附件時保留帳目本身。
- 新增帳目與編輯帳目的附件入口已一致支援手機拍照與選擇既有照片 / 檔案。
- iOS 附件同步失敗、重試與附件連結開啟仍需實機回歸。

### 同步管理

- Offline First
- Pending Queue
- Pending Badge
- 手動同步
- 自動同步
- 帳目同步
- 附件同步
- Supabase realtime 更新
- 30 秒固定刷新 fallback
- 頁面重新聚焦、網路恢復、頁面可見時重新刷新

### 匯出

- Excel 匯出
- 匯出記帳日期
- 匯出附件網址

# 七、共同清單

## 功能說明

管理旅程所有成員共同使用的清單。

## 旅行工具規格

| 項目 | 內容 |
|------|------|
| 儲存位置 | Trip JSON seed + localStorage 進度 |
| 資料擁有者 | Trip |
| 適用對象 | Guest、User、Trip Editor、Super Admin |
| 權限規則 | Guest / User 可見不可勾選；Trip Editor / Super Admin 可勾選 |
| 是否可編輯 | Trip Editor / Super Admin 可透過管理模式新增 / 編輯 / 刪除項目 |
| 同步方式 | 本機持久化 + Supabase shared checklist 最小雲端同步 |
| 生命週期 | 建立 Trip 後即可使用，刪除 Trip 時一併刪除 |

## 管理資料

- Checklist
- Checklist Item

## 功能能力

### 清單管理

- 讀取 Trip JSON seed 清單

### 項目管理

- Trip Editor / Super Admin 可新增、修改、刪除共同清單項目。
- 管理操作需先進入「管理」模式，日常瀏覽時不直接顯示新增、編輯、刪除入口。

### 完成狀態

- 勾選完成
- 依 `tripId` 保存於 localStorage
- 進度計算忽略已不存在的 seed item id

### 同步範圍

- 若雲端沒有 shared checklist，使用 Trip JSON seed 初始化。
- 共同清單優先讀 Supabase shared checklist。
- `trip_editor` / `super_admin` 可同步勾選狀態。
- 若多人同時修改同一筆共同清單項目的同一欄位（包含勾選狀態），以最後成功上傳到 Supabase 的資料為準，Realtime 事件或下一次讀取時同步回本機；不新增衝突 UI。
- 離線／結構修改（新增、刪除、分類、標籤、排序）依《16_V3.4.1_離線狀態與OtherInfo本機優先同步規格》的修改前快照、本機結果及最新雲端結果三方合併；pending 優先且不得被遠端刷新覆蓋。

### 顯示

- 排序
- 篩選
- 搜尋

# 八、私人確認清單

## 功能說明

管理個人準備事項。

私人確認清單是獨立 Travel Tool，入口位於左上角功能選單中共同檢查清單下方。

## 旅行工具規格

| 項目 | 內容 |
|------|------|
| 儲存位置 | localStorage + Supabase（依權限） |
| 資料擁有者 | 個人 + Trip |
| 適用對象 | User、Trip Editor、Super Admin |
| 權限規則 | Guest 不可使用；登入使用者僅可查看與管理自己的私人清單 |
| 是否可編輯 | 可新增、編輯、刪除、勾選自己的項目 |
| 同步方式 | User 僅本機；Trip Editor / Super Admin 可同步自己的私人清單 |
| 生命週期 | 依 `userEmail + tripId` 建立本機資料 scope |

## 管理資料

- Private Checklist
- Private Checklist Item

## 功能能力

### 項目管理

- 新增私人項目
- 編輯私人項目
- 刪除私人項目

### 完成狀態

- 勾選完成
- 顯示私人準備進度
- F5 後保留本機資料
- 顯示同步中、已同步、同步失敗狀態

### 權限限制

- Guest 不顯示私人確認清單入口。
- User 可使用自己的本機私人清單，但不做雲端同步。
- Trip Editor / Super Admin 可同步自己的私人清單，且不得讀取其他使用者私人清單。
- 本機 ownership 使用 `userEmail + tripId`。
- 雲端 ownership 使用 `owner_user_id = auth.uid()` 與 `trip_id`。
- 雲端 item 使用 `client_item_id` 對應本機 item id。

# 九、其他資訊

## 功能說明

管理旅程參考資訊與旅行資訊。

## 旅行工具規格

| 項目 | 內容 |
|------|------|
| 儲存位置 | 預設資料 + localStorage 本機覆寫 + Supabase 最小雲端同步 |
| 資料擁有者 | Trip |
| 適用對象 | Guest、User、Trip Editor、Super Admin |
| 權限規則 | 依角色權限過濾；有權限者可管理，其他角色唯讀 |
| 是否可編輯 | 有管理權限者需先進入管理層，才顯示新增、編輯、刪除 |
| 同步方式 | 本機 / Trip content 備援 + Supabase 讀取、upsert、軟刪除 |
| 生命週期 | 預設資料隨 Build 發布，本機覆寫保存在使用者裝置 |

## UI 管理規格

- 預設畫面以瀏覽資訊為主。
- 有管理權限者顯示「管理」入口。
- 點選「管理」後才顯示新增、編輯、刪除。
- 管理層需提供「退出」按鈕回到瀏覽模式。
- 領隊導遊聯絡資訊與自駕租車須知需比照其他資訊採相同模式。

## V3.5.0 敏感資訊可見範圍（已定案、程式已補全）

- 維持目前 Folder 為第一層分類、Other Info 卡片為第二層內容的結構，不新增敏感資料夾或第三層分類。
- 進入管理編輯時預設為「一般資訊」，一般資訊不顯示「資訊可見範圍」選項，儲存按鈕維持原本流程。
- 編輯者可按「新增敏感資料」快捷入口建立或編輯敏感卡片；此模式自動套用「僅行程管理者可查看」。
- 「僅行程管理者可查看」只允許目前 Trip 被指派的 `trip_editor` 與 `super_admin` 讀取；Guest、User 與其他 Trip 的編輯者完全看不到卡片、數量或存在提示。
- 現有未限制卡片及新的一般資訊預設為一般資訊；既有受限制卡片編輯時維持敏感資料模式。
- 按下儲存敏感資料時才顯示二次提醒：「訂房編號、訂位代碼、租車確認碼、私人電話、個資或受限文件連結，請設為『僅行程管理者可查看』。一般公開網路連結可視為非敏感；固定帳號保護的雲端文件仍屬敏感內容。」；一般編輯畫面不直接顯示這段文案。
- 有權限者查看受限制卡片時，卡片顯示鎖頭圖示及「僅行程管理者可查看」標示。
- 權限以整張卡片為單位；一般資訊與敏感資訊混在同一張卡片時，編輯者應拆成不同卡片。
- 複製、排序、編輯、同步與離線快取均須保留可見範圍。
- 本版納入 V3.4.11 BUG024 修正：其他資訊同步失敗時提供手動重新同步；同步採先 UPDATE、無對應資料列才 INSERT；`trip_editor` 不得修改參與者／登入 Email 或刪除整個旅程，其餘旅程編輯權限維持不變。
- V3.5.0 已發布並採 `FORCE_UPDATE = true`；013／014 migration、角色回歸、舊版 PWA 升級及 Android／Chrome PWA 啟動／版面驗證已完成；iOS 因目前無設備而保留未驗證並暫時跳過，發布後驗證已於 2026-08-26 結案。
- V3.5.1 已完成：其他資訊、領隊／導遊資料及共同準備清單支援同一 Trip 的跨裝置即時刷新；以 Realtime 事件觸發 RLS-safe 重新載入，並保留離線同步佇列與既有角色權限。
- 相關模擬圖已完成並經 Product Owner 確認；程式依本方案實作，後續以角色與同步回歸驗證為準。
