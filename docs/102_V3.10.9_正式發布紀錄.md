## 4. 修正路徑與本機驗證背景

- 原始邏輯缺陷：後端與前端先前部分依快取年齡是否達 24 小時（`isStale`）決定是否顯示 W09。若目的地日期／到達時間已過，但快取取得時間尚未滿 24 小時，或頁面重載後直接讀取已持久化的 `refresh_stopped` 快取，可能保留天氣值卻未持續顯示 W09「預報已超過有效期限，目前顯示的是歷史資料」。
- V3.10.9 Git 修正路徑：後端改依目的地日期／到達時間資格（`date_passed`／`arrival_passed`）選擇 W09；前端對 `ineligible` 且保留舊天氣資料的結果，以及重新載入後已標記 `refresh_stopped` 的快取，均固定使用 W09，不再以快取年齡決定是否顯示歷史資料提示。
- 該次歷史記錄中，`scripts/verify-v3101-weather-forecast.mjs` 已更新，以涵蓋新判斷條件。記錄的本機驗證包括 `npm run verify:v3101-weather-forecast`、`npx --yes deno check supabase/functions/weather-forecast/index.ts`、完整 `npm run build`（包含天氣／時區回歸與 TypeScript）。
- 已記錄的本機合成快取驗證：以 6 小時前取得、`refresh_stopped=true` 且目的地日期已過的合成快取測試頁面重載，舊天氣值仍保留，並顯示 W09「預報已超過有效期限，目前顯示的是歷史資料」。測試後已還原原本 localStorage 天氣快取，沒有留下合成資料。
- 此段是 V3.10.9 的歷史測試記錄，不代表正式網站已通過 W09 端到端驗收，也不代表正式 Edge Function 已包含 Git 修正。

- 正式網站真實行程仍需驗證「到達時間已過但快取未滿 24 小時」及「停止更新後重新載入」兩種情境：舊天氣值應保留、W09 提示持續顯示，且不再發出天氣刷新請求。
