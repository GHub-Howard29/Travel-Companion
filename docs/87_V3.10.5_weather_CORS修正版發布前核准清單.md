# V3.10.5 weather-forecast CORS 修正版發布前核准清單

> 整理日期：2026-10-18
> 狀態：已完成 3.10.5 source commit／tag；本文件保留 CORS 修正範圍與驗證界線。後續 3.10.6 RC 不沿用本文件作為正式驗收證據。

## 1. 已確認根因

- 正式 APP 的 preflight OPTIONS 回應 HTTP 200，但 `Access-Control-Allow-Headers` 遺漏前端全域 Supabase client 會送出的 `x-travel-companion-client-id`。
- Supabase Edge Logs 只看到 `OPTIONS 200`，沒有正式 APP 的 POST invocation。
- 瀏覽器因此在 POST 到達 Edge Function 前阻擋請求，最後回報 `net::ERR_FAILED`；前端再顯示「天氣服務逾時」。

## 2. 修正範圍

- `weather-forecast` CORS 白名單加入 `x-travel-companion-client-id`。
- 靜態契約驗證加入此標頭防漏檢查。
- 版本升為 V3.10.5，並將 V3.10.4 補入 App 版本歷史。
- 不新增 migration、不修改正式資料、不輪替 secrets。

## 3. 安全與資料邊界

- CORS 只允許既有前端必要標頭；不放寬授權或資料權限。
- Edge Function 仍只記錄安全錯誤碼與 opaque trace ID，不記錄 API key、Authorization token、Trip／地點識別值或 provider 原始回應。
- 正式部署只包含已驗證的 Edge Function 與前端 bundle。

## 4. 發布前驗證

- `npm run verify:v3101-weather-forecast`
- `npm run verify:release-history`
- TypeScript、ESLint、完整 production build、PWA 與 browser-security。
- `npm run verify:docs-links` 與 `git diff --check`。
- 正式 smoke 必須確認 OPTIONS 200、未授權 POST 401，並確認已登入正式 APP 的實際 POST 出現在 Edge Invocations。
