## 1. 目的與問題背景

解決每日行程卡片在新分頁、瀏覽器重新啟動、PWA 冷啟動或跨裝置更新後，仍可能顯示舊的本機 Trip 快照、需要使用者手動要求更新的問題。

預期行為：有網路且使用者已完成必要 session／權限準備時，啟動過程必須向雲端重新驗證行程卡片資料；若雲端版本較新且本機沒有尚未同步的卡片修改，安全更新本機快取及目前畫面。離線時仍可使用本機資料。

此設計不是將所有模組改為雲端覆蓋本機，也不是刪除 Offline First。

## 2. 強制範圍界線（最高優先）

### 2.1 唯一適用對象

- Trip 的每日行程卡片資料（`daysData`／每日行程內容）。
- 因取得、比較、套用每日卡片所必要的 Trip metadata／revision／雲端版本資訊。
- 顯示每日卡片的目前 Trip 畫面與本機 Trip 卡片快取。

### 2.2 明確排除：既有同步規則不得變更

本次不得修改、重構或改變以下模組的同步機制、觸發條件、快取、Pending Queue、Realtime、權限或失敗重試規則：

- 帳本與共用帳本（expenses）。
- 帳本附件／照片上傳及同步。
- Checklist／共同準備清單。
- Other Info／其他資訊。
- 私人清單。
- 領隊／導遊資料。
- 封面照片及其他照片資源。
- 天氣預報、天氣快取與 weather-forecast Edge Function。
- 使用者個人資料、登入／登出及角色權限本身。
- 任何不屬於每日行程卡片的獨立模組。

上述功能現有同步方式維持原狀。本次即使檢查時發現其程式碼，也不得順手整理或套用新策略；若行程資料與其他模組共用 Trip record 欄位，必須精確更新每日卡片欄位，不可用舊快照覆蓋其他欄位。

## 3. 已定案的行為規則

| 情境 | 每日行程卡片應有行為 |
|---|---|
| 新分頁／瀏覽器冷啟動／PWA 冷啟動，線上且 session 就緒 | 先以本機資料快速顯示；背景讀取雲端權威資料，完成比對後自動更新本機卡片快取及目前畫面 |
| 啟動時離線 | 使用本機快取，不等待網路、不清空資料、不阻擋進入 App |
| 網路恢復 | 自動觸發一次受控雲端重新驗證；同一時間重複事件必須去重 |
| 從背景回到前景／頁面重新可見 | 依 revision／版本核對；無變更不得無謂重載整份資料 |
| 雲端較新、本機卡片無 pending 修改 | 自動套用雲端卡片資料，不要求使用者手動點更新 |
| 本機存在尚未成功同步的卡片修改 | 不可無條件覆蓋；保留本機 pending，進入安全合併或衝突流程 |
| 雲端讀取失敗、逾時、權限狀態未確認 | 視為「無法確認」，不是雲端空資料；不得清空或覆蓋本機資料 |
| 確認雲端沒有該 Trip／權限已撤銷／Trip 已刪除 | 沿用既有 access／tombstone／刪除保護規則，不得把一般讀取錯誤誤判成刪除 |
| 使用者正在編輯卡片但尚未保存 | 不得讓背景刷新覆蓋表單草稿；需等待、提示或安全合併 |
| 成功套用雲端版本 | 同時更新本機權威快取、Trip workspace metadata 與目前顯示的卡片 state，避免只更新清單卻畫面仍舊 |

「強制」指線上冷啟動必須執行雲端重新驗證，不代表不論 pending、衝突、權限或讀取失敗都強制覆蓋本機。

## 4. 資料安全與衝突規則

1. 不可用 `updatedAt` 單一時間戳作為完整 dirty／pending 判斷。
2. 需為每日行程卡片建立明確的本機同步狀態，至少能區分 `synced`、`pending`、`conflict`；並保存可比較的基準雲端版本／`cloudUpdatedAt`。
3. Trip 卡片編輯在網路成功同步前，需可辨識本機尚未提交的變更；離線與失敗時不得清除 pending。
4. 本機 clean 且雲端讀取成功時，雲端資料為套用目標；本機 pending 時，採明確的三方比較（基準雲端版本、本機修改、目前雲端版本）決定安全合併或衝突，禁止簡單 last-write-wins 覆蓋整份每日卡片資料。
5. 儲存時繼續使用既有 optimistic-lock／version-recovery 安全邊界；不得用未檢查的舊 `updatedAt` 強行 upsert。
6. 只可更新每日行程卡片欄位。保留 Trip 其他 content 欄位、Other Info、帳本、清單、參與者 Email map、封面與附件。
7. 雲端 strict read 必須將「成功且 0 筆」、「成功但無權限／已刪除」及「網路／伺服器讀取失敗」分別表達，不可將錯誤收斂成 `[]` 後讓呼叫端誤判。
8. 刷新成功必須更新目前作用中的 Trip detail／畫面 state；不能只更新 localStorage 或 Trip meta list。
9. 跨分頁／跨裝置同時編輯、使用者尚在表單編輯、離線佇列與照片資源必須有獨立測試。此規格不授權變更非卡片模組的佇列。

### 4.1 衝突判定與自動合併（定案）

- 衝突比對的基本單位為每日行程卡片的穩定 `card.id`；卡片所在日期（`dayKey`）與卡片內容分開比較，不能只以陣列索引或整份 `daysData` 判斷。
- 使用三方比較：基準快照（base）、本機修改（local）、最新雲端快照（cloud）。僅一端變更的欄位／卡片採該端結果；兩端變更後結果相同，視為已收斂；兩端修改不同且無法安全合併，才建立衝突。
- 不同卡片各自修改、單邊新增、單邊刪除及互不重疊的欄位修改，應自動合併，不要求使用者逐張確認。
- 同一卡片兩端修改相同欄位且結果不同，建立該卡片衝突；刪除與另一端修改同卡片衝突；同卡片被兩端搬移到不同日期衝突。
- 單邊跨日搬移與另一端只修改該卡片的其他獨立欄位，可在保留搬移結果及內容修改的前提下自動合併；若同時改動日程位置／排序或違反卡片唯一性，必須交由使用者確認。
- 排序是獨立於卡片欄位的資料。若只有一端變更某日順序，採用該端順序並納入另一端新增／未變更卡片；若兩端對同一日產生不相容的排序變更，建立該日的「排序衝突」，不得靜默固定採 local 或 cloud 順序。
- 舊資料缺少穩定 card ID、同一份資料內出現重複 ID、或無法唯一識別卡片時，不得猜測配對或自動合併；保存完整本機版本並要求人工處理／資料修復。

### 4.2 衝突資料保存與使用者選擇（定案）

- 衝突狀態必須可持久化保存 base、當時觀察到的 cloud snapshot／版本，以及 local pending snapshot；每一筆衝突另保存類型、卡片 ID／日期、兩端版本與衝突欄位。不能只保存不可供 UI 使用的 `lastError` 字串。
- 使用者可逐筆處理衝突：
  1. **保留本機版本**：整張卡片採本機快照；
  2. **採用雲端版本**：整張卡片採雲端快照；
  3. **逐欄選擇**：只對可安全獨立判斷的欄位選擇本機或雲端值。
- 逐欄處理至少涵蓋時間（含到達／離開時間）、標題、類型、說明、地點文字、地點實體（Place）、天氣顯示、交通模式／交通計算選項及其他資訊分類連結。`type` 與 `typeColor` 等具語意關聯的欄位應成組處理；Place identity 與自由文字地點不可任意拼接。
- 交通估算／距離／時間是由起訖地點、交通模式等資料衍生；只要其依賴欄位被選擇或合併改變，必須使不再適用的估算失效／重新計算，不得留下看似有效但實際指向舊地點的結果。
- 封面照片及其來源／作者／授權／儲存資訊視為一個完整組合欄位，不做碎片拼接；在雲端保存成功前不得清理任何可能仍被任一版本引用的資產。
- 刪除 vs 修改衝突必須明確選「保留刪除」或「保留修改後卡片」；跨日搬移衝突必須明確選擇日期／卡片內容；排序衝突提供採本機順序、採雲端順序，不能只顯示一般卡片欄位。
- UI 在每日行程頁顯示待處理筆數與同步狀態；無衝突卡片照常可用，衝突卡片需清楚標示並提供檢視／處理入口。多筆衝突可逐筆解決，不要求一次全部完成；未解決項目繼續保護本機資料且不得自動重試覆蓋。
- 離線時可查看本機／雲端已保存的衝突版本並先選擇方案；離線選擇只保存為本機「待套用解決方案」，不可顯示已同步。重新上線後仍須重新核對雲端版本。

### 4.3 衝突解決提交安全（定案）

1. 使用者選擇只代表同意處理當時顯示的 base/local/cloud 三個版本，不代表允許覆蓋之後才發生的新修改。
2. 點擊套用時，先持久化使用者選擇，再重新讀取最新雲端快照與 `updatedAt`／revision。
3. 針對最新雲端快照重新執行三方比對：若衝突卡片／欄位已被再次變更，保留原選擇與所有新版本，更新衝突細節並要求再次確認；不得以先前使用者同意直接覆蓋。
4. 無新衝突且 optimistic-lock 條件仍成立時，只提交每日卡片 `daysData`；成功確認雲端回讀後，才標記已同步並清除相應衝突快照。
5. 多筆衝突逐筆完成；任何未處理衝突仍維持 `conflict`，不能因另一筆已成功而把整個 Trip 標成 `synced`。
6. 儲存失敗、雲端讀取不明、權限未確認或 revision 改變時，保留 base/local/cloud／選擇結果及錯誤原因，提供重試；禁止假裝成功或回退丟棄本機修改。

### 4.4 衝突處理 UI 呈現（定案）

- 每日行程頁上方顯示簡短提示，例如「有 2 張行程卡片需要確認」，並提供「檢視衝突」入口；未有衝突時不佔用畫面。
- 清單列出每張衝突卡片的日期、標題與衝突類型；排序衝突以日期為單位顯示。
- 衝突詳情並列顯示「本機版本」與「雲端版本」，欄位不同處做視覺標示。提供整張採本機／整張採雲端／逐欄選擇；刪除、搬移、排序均使用相應專用選擇控制。
- 使用者可以稍後處理並返回行程頁；保留衝突不阻擋讀取其他卡片，但阻擋會覆蓋衝突卡片或受其影響排序的同步寫入。
- 明確顯示「待處理」與「已同步」差異；線上送出未確認前不能顯示完成，離線選擇只能顯示「待上線套用」。
