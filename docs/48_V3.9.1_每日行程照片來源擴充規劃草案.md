- 階段：僅列入規劃，需求與設計尚未完成討論。

## 子方案 A：中文搜尋自動擴充英文關鍵詞

- 評估中文搜尋時擴充英文關鍵詞，並合併、去除重複候選。
- 待討論地點詞彙來源、專有名詞準確性、失敗降級、API 成本及是否顯示提示文案。
- 本子方案可獨立評估與核准，不因多來源切換方案而被取代。

## 子方案 B：Commons／Pexels／Pixabay 來源切換

- 每日行程卡片照片來源預計評估 Commons、Pexels、Pixabay。
- 初步偏好由使用者切換來源後重新搜尋或「換一批」，不自動同時呼叫全部來源。
- 待討論各來源命中率、API 額度、快取、授權、下載保存、分頁與無結果降級。
- 本子方案可獨立評估與核准，不取代中文搜尋自動擴充英文關鍵詞方案。

## 共同邊界

- Google Place Photos 維持地點搜尋候選確認用途，不自動作為每日行程卡片照片。

## 既有 Commons 搜尋待改善：零結果與去重提示

- 2026-09-14 正式站回饋：首次搜尋一張候選都沒有時，畫面卻可能顯示「這一批沒有新的 Commons 照片，請再按一次換一批。」；此文案語意不正確。
- 首次搜尋零結果時，應提示使用者更換或調整搜尋關鍵字；只有已取得首批候選、使用者實際執行「換一批」，且該批結果經去重後沒有新候選時，才可顯示「這一批沒有新的照片」類提示。
- 現行前端會以已看過的 Commons `fileTitle` 集合過濾重複候選；開發前須以測試確認集合是否僅限同一對話框與同一搜尋詞、換詞與關閉重開的重置時機，以及首次搜尋是否誤沿用先前紀錄。
- 待討論並定稿至少三種狀態及文案：來源端零結果、仍有下一頁但本批全數重複、已無下一頁且沒有更多新照片。
- 本項只記錄問題與驗收方向；目前不得修改 UI、可見文案或程式。

## 開發前必須完成的討論

- Pexels、Pixabay 的實際 API 命中率、額度、快取、下載保存及授權標示規則。
- 來源切換流程、預設來源、分頁狀態與無結果降級。
- 首次搜尋／換一批的狀態判定、`fileTitle` 去重紀錄範圍、換詞與重開重置規則，以及各狀態可見文案。
- 中文轉英文的詞彙來源、專有名詞準確性、失敗降級及是否需要外部翻譯服務。
- 多來源候選的資料契約、去重方式、Storage 保存、引用與清理規則。
- 桌面與 390×844 手機版 UI、所有可見文案及無障礙操作。
- 成本、安全、隱私、服務條款與離線行為。
- 測試範圍、發布停止條件及版本相容策略。
