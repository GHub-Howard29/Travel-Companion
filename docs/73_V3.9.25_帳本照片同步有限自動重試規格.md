# V3.9.25 帳本照片同步有限自動重試規格

> 狀態：2026-10-08 實作與完整驗證完成；Product Owner 已授權跳過 RC 直接正式發布。專用 regression、TypeScript、ESLint、完整 production build、PWA generateSW 與 browser-security 均通過。

## 目的

改善共用帳本有照片附件時，使用者按下「同步照片」後因短暫網路、Storage 或 Supabase 錯誤而必須反覆手動重按同步的問題。

本版只補強「使用者已手動啟動照片同步後」的有限自動重試，不改變既有 Offline First 帳目同步規則，也不把照片改成恢復連線後自動續傳。

## 已定案規則

1. 使用者按一次「同步照片」後，第 1 次立即執行。
2. 在線上暫時性失敗時，每隔 3 秒自動重試。
3. 第一次手動啟動的同步算第 1 次，最多共嘗試 5 次。
4. 每一輪只帶入仍失敗的照片；已成功照片不再重傳。
5. 第 5 次仍失敗即停止，不再背景持續重試。
6. 使用者再次按「同步照片」時，重新從第 1/5 次開始。
7. 權限、登入／JWT、RLS、找不到本機照片等明確不可恢復錯誤不做無意義的 5 次重試。
8. 同步中的按鈕顯示目前嘗試次數，例如「同步中 2/5...」。

## 離線規則維持不變

### 一開始就是離線

不啟動照片同步，沿用既有文案：

> 目前離線，請連線後再同步照片。建議在 Wi-Fi 環境下上傳。

### 離線新增帳目與照片

若照片所屬帳目仍是本機 pending 帳目，先讓帳目依既有 Offline First / Pending Queue 規則同步到雲端，再由使用者按「同步照片」。

既有詳細說明文案保留：

> 有離線新增的照片，請先連線讓帳目自動同步後，再按同步照片。

### 自動重試期間斷線

- 立即停止本輪自動重試；即使正在等待下一次 3 秒間隔，也由 `offline` event 提前結束等待。
- 未同步照片持續保留在本機。
- 恢復連線後不自行續傳照片。
- 使用者再次按「同步照片」才開始新一輪 1/5～5/5。

停止文案：

> 網路已中斷，已停止照片自動重試。未同步照片會保留在本機；請連線後再次按「同步照片」。

## 第 5 次仍失敗

同步流程停止並保留本機附件，文案：

> 照片同步完成 X 筆，失敗 Y 筆。已停止自動重試，失敗項目會保留本機照片；請稍後再次按「同步照片」。

若可取得錯誤原因，延續既有行為附在下一行。

## 實作重點

- `src/hooks/useExpenseBook.ts`
  - `ATTACHMENT_SYNC_MAX_ATTEMPTS = 5`
  - `ATTACHMENT_SYNC_RETRY_DELAY_MS = 3000`
  - 以 `remainingItems` / `retryItems` 確保下一輪只處理仍失敗附件。
  - 明確不可恢復錯誤不加入下一輪。
  - `offline` event 可中斷 3 秒等待。
  - 完成或停止後清除同步中狀態，下一次手動按同步重新開始。
- `src/components/expense/ExpenseScreen.tsx`
  - 同步按鈕顯示 `同步中 N/5...`。

## 驗證

新增：

`npm run verify:v3925-expense-attachment-retry`

至少驗證：

- 5 次上限。
- 3 秒重試間隔。
- 只重試失敗項目。
- 不可恢復錯誤停止重試。
- 完全離線文案不變。
- 重試期間斷線立即停止。
- 第 5 次失敗後等待使用者再次手動同步。
- UI 顯示目前嘗試次數。
