# V3.6.1 Android 記帳金額欄位版面修正規格

> 狀態：待開發；問題、修正範圍與驗收條件已確認
>
> 建立日期：2026-08-31
>
> 版本類型：Patch

---

## 一、問題說明

在記帳本的「新增一筆旅費」表單中，Android 手機使用 Chrome 網頁版或已安裝 PWA 時，聚焦「金額」欄位並開啟數字鍵盤後，欄位會超出卡片與畫面右側。

- Android Chrome：已重現。
- Android PWA：已重現。
- iOS Safari／standalone PWA：目前未知，必須一併驗證。
- 電腦瀏覽器／PWA：目前未重現，修正後仍須回歸。

此問題是輸入列的響應式版面異常，不是金額資料、Supabase 或同步錯誤。

---

## 二、原因判定

目前新增表單的幣別與金額欄位使用 `flex` 橫向排列：

- 幣別選單依內容保留自身寬度。
- 金額欄位使用 `flex-1`，但沒有 `min-width: 0`、`width: 100%` 或最大寬度限制。
- Android Chrome 聚焦原生 `input[type="number"]` 時可能保留較大的內在寬度；父層可用空間不足時，欄位不會如預期縮小，最後被全頁 `overflow-x: hidden` 裁切。

既有帳目編輯列已使用 `minmax(0, 1fr)` 與 `min-w-0`，風險較低，但新增與編輯兩種金額欄位應採一致的響應式規則。

---

## 三、待開發修正

1. 將新增表單的「幣別＋金額」列改為明確的兩欄 Grid：幣別欄保留必要寬度，金額欄使用 `minmax(0, 1fr)`。
2. 金額欄位加入 `w-full min-w-0 max-w-full box-border`，確保 Android 原生數字輸入控制項不能撐出父層。
3. 幣別選單加入必要的縮放／截斷保護，所有 `SUPPORTED_CURRENCIES` 文案都必須留在卡片內。
4. 為新增與編輯金額欄位設定一致的 focus ring／outline，聚焦提示必須清楚但不得超出卡片或改變欄位寬度。
5. 同步檢查既有帳目編輯列，維持相同的欄位寬度保護；不得只修新增表單而留下編輯狀態的裝置差異。
6. 保留金額欄位目前的資料格式與提交邏輯，不在本修正版變更小數、正負值、四捨五入或既有資料相容性。
7. 保留全域表單控制項至少 `16px` 的字級，避免 iOS 聚焦時自動放大。
8. 不加入 `maximum-scale=1` 或 `user-scalable=no`，不得用禁止縮放掩蓋版面問題。

---

## 四、輸入格式檢查

- 新增與編輯金額欄位維持一致的 `type="number"` 與數字鍵盤提示。
- placeholder 維持「金額」，輸入值仍由既有 `newAmount`／`editDraft.amount` 狀態管理。
- 送出時維持目前 `Number(...)`、非數字阻擋及既有整數處理，不在 V3.6.1 擴張金額資料模型。
- 空白、非數字、極長數字與貼上內容不得造成水平溢出；既有有效金額必須可正常儲存。
- 顯示金額的千分位與帳本統計格式不得受版面修正影響。

---

## 五、驗收條件

### 行動裝置

- Android Chrome 網頁版與 PWA 在直向、橫向及數字鍵盤開啟時，金額欄位右框完整留在卡片內。
- 至少驗證 320、360、393 與 412 CSS px 寬度，不得出現頁面水平位移、裁切或橫向捲動。
- 逐一切換所有支援幣別，幣別與金額欄不得互相覆蓋。
- 新增與編輯金額欄位都要驗證空白、一般金額與長數字。
- iOS Safari 與 standalone PWA 必須檢查鍵盤開啟、聚焦、縮放及離開欄位後 viewport 是否恢復；不得破壞既有 iOS viewport 修正。

### 桌面與功能回歸

- 桌面 Chrome／Edge 與 PWA 的新增、編輯、儲存、取消及錯誤處理維持正常。
- 個人帳本與共用帳本都可新增及編輯。
- 拍照／相簿附件、付款人、幣別切換及「記帳」按鈕不因欄位版面調整而位移或失效。
- `npm run lint` 與 `npm run build` 通過。

## 六、發布與資料邊界

- V3.6.1 不需要 Supabase migration、Edge Function、RLS、Storage 或 Google Cloud 設定變更。
- 預設 `forceUpdate: false`；除非回歸發現舊版會造成資料損壞，否則不強制更新。
- 本版只修正記帳金額欄位的跨裝置版面與格式一致性，不包含 V3.7.0 的時間連動調整功能。
