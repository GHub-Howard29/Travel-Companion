## 1. RC 範圍

- DEV 安全：非 loopback Supabase URL 硬阻擋，避免下載專案的人以 DEV 測試帳號誤連正式資料庫。

- 天氣穩定性：要求 lease release RPC 明確回傳 true，修正同一 token 的過期 lease 回寫與失敗清理。
- UI：修正天氣來源選單在窄螢幕超出 viewport 的問題，保留 Open-Meteo 與 CC BY 4.0 標示。
- 安全文件：記錄 Supabase Advisor 既存 RLS、SECURITY DEFINER、pg_net 與 Auth 密碼防護提醒，留待後續安全掃描再審查；本 RC 不直接修改這些既存設定。

### 目前判讀與下一步

- 新地點跨日複製與天氣取得已通過，表示一般新座標路徑可運作；不能據此推定舊座標快取路徑正常。
- D2 來源網址已由使用者提供並核對：座標為 `25.0884972, 121.5243504`，日期為 `2026-10-20`，格式符合實際查詢；仍需 D1／D3 失敗時各自的診斷碼或來源網址，以區分日期請求、快取與 lease 問題。
- 程式中座標快取依 `place_id` 共用，天氣資料與 lease 依 `(place_id, forecast_date)` 分開。2026-10-18 已獲授權進行正式 Edge Logs 與資料庫唯讀查核：台南與日月潭的 D1 成功、D2–D5 的 `fetched_at` 為 null 且 `last_refresh_error=WEATHER_CACHE_WRITE_FAILED`；旗津對應資料五天皆成功，須以 trace／卡片 ID 再對齊使用者畫面。這已排除單純「沒有建立後續日期快取列」的解釋，但尚未區分成功回寫 RPC 回傳 false、RPC SQL error 或 lease／座標條件未命中，不能宣稱根因已確診。後續順序與待驗假設見《[92_V3.10.7_多日天氣快取回寫追查計畫](92_V3.10.7_多日天氣快取回寫追查計畫.md)》。
- 座標快取若為 `failed` 且一小時內更新，會回傳 `PLACE_DETAILS_RETRY_COOLDOWN`，目前證據不足以認定它是本次根因。正式 migration history 缺少 `20261018100000`，但正式 DB 已有 `source_url` 欄位／約束／函式內容，列為獨立的 migration 紀錄漂移風險。另經正式函式定義唯讀核對，正式 `tc_weather_release_lease` 仍先鎖天氣預報列，再檢查座標；本機 `20261018140000_v3101_weather_release_lock_order.sql` 則改為先鎖座標列再鎖預報／lease 列，並重驗 TTL，兩者尚未一致。已在本機 Edge Function 加入安全診斷，區分回寫 RPC SQL error 與回傳 `false`；本機 Supabase transaction + rollback 測試 3 地點 × 5 天，12 次正常回寫成功、3 次刻意座標不匹配正確回傳 `false` 並可清理 lease。此測試證明函式契約分支可正常運作，尚未重現正式故障。

## 5. 2026-10-18 除錯暫停點與交接

- 使用者指定的重現網址是本機 `http://localhost:4173/Travel-Companion/`。檢查本機 Vite 轉譯後設定確認 Supabase URL 指向 `http://127.0.0.1:54321`，因此本機測試會呼叫本機後端。
- 本機 `POST /functions/v1/weather-forecast` 回應 HTTP 503。`supabase start` 顯示 Edge Runtime 容器停止；嘗試啟動時，Docker 回報掛載來源 `supabase/.temp/start-secrets/supabase_edge_runtime_travel-companion/main/index.ts` 是目錄，而容器目的地 `/root/index.ts` 預期為檔案。沒有刪除／重建 `.temp`、沒有刪除 Docker volume，也沒有改動資料庫或正式環境。
- 這表示本機目前無法作為 RPC 根因的重現環境；正式 `function_logs` 曾記錄 4 次 `WEATHER_CACHE_RELEASE_RETURNED_FALSE`，但不能只憑 localhost 畫面把兩者視為同一批請求。正式根因仍未確診。
- **後續待辦順序**：(1) 先安全修復本機 Edge Runtime 容器的掛載路徑／產生流程，保留本機資料與工作樹；(2) 確認本機 weather-forecast 回應不再是 503；(3) 唯讀逐條核對正式 `tc_weather_release_lease` 的 UPDATE 條件與 lease 到期判斷，並補足本機隔離回歸案例；(4) 在本機重測 D1 新增地點及複製至 D2–D5；(5) 如仍需正式端驗證或套用 migration／RPC 修正，另行取得明確授權。根因確認前不部署、不改正式 DB／RPC／Secrets、不清正式快取、不建立正式 tag 或合併 main。
