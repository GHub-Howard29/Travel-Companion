# 權限設定資料表

本文件是 Travel Companion 目前權限設定的集中對照表。程式實作以
`src/permissions/permission.ts`、`src/permissions/roleMapper.ts` 為準；本文件供產品確認、測試與後續調整時查閱。

最後更新：2026-08-25
狀態：V3.4.11 為 V3.5.0 的上一個正式發布基準；V3.5.0 卡片安全方案與 BUG024 權限修正已定案並完成程式補全，Supabase migration 已套用，角色實機驗證已通過並完成發布；V3.5.0 採 `FORCE_UPDATE = true`。

---

## 一、角色判定

| 角色 | 判定方式 | 範圍 |
|---|---|---|
| `guest` | 未登入 | 所有旅程皆為訪客視角 |
| `user` | 已登入，但不是目前旅程的編輯者 | 僅一般使用權限 |
| `trip_editor` | 已登入，且 `admin_users` 內有目前 Trip 的 `trip_editor` 指派 | 僅被指派的旅程 |
| `super_admin` | 已登入，且 `admin_users` 內有 `super_admin` 身分 | 所有旅程 |

`trip_editor` 切換至未被指派的旅程時，會以 `user` 權限使用該旅程。

「預設首頁」依登入帳號＋Trip 儲存在本機；不會影響其他使用者，也不會同步到雲端。

## 三、私人確認清單的資料隔離

私人確認清單以「登入使用者 + Trip」為獨立範圍：

- `guest` 沒有入口，也不能使用。
- 已登入的 `user` 可建立與管理自己的本機私人清單，但不會同步雲端。
- `trip_editor` 與 `super_admin` 可同步自己的私人清單到雲端。
- 雲端以 `owner_user_id = auth.uid()` 限制讀寫；每位使用者只能讀寫自己的私人清單。
- `super_admin` 的旅程管理權不包含檢視、編輯或同步其他使用者的私人清單。
- 私人清單勾選後，畫面會自動將已勾選項目置底；這不會影響其他使用者的清單。

## 四、資料與同步範圍

| 資料類型 | 雲端資料範圍 | 本機／個人隔離規則 |
|---|---|---|
| 每日行程、領隊／自駕資訊、其他資訊 | 由目前 Trip 的編輯者／管理員維護 | guest / user 僅讀取可見資料 |
| 共同檢查清單 | 由目前 Trip 的編輯者／管理員維護共用雲端版本 | user 使用帳號＋Trip 分隔的本機副本；不影響共用雲端版本 |
| 共用帳本 | 目前 Trip 的 A+B 聯集；`owner_user_id` 控制記錄 ownership，`payer` 只控制分帳 | user 使用自己的個人本機帳本；編輯者的離線 queue 依 `tripId + owner_user_id` 隔離 |
| 外幣換算 | 目前 Trip 的編輯者／管理員共用雲端歷史 | guest / user 僅用本機換匯資料 |
| 私人確認清單 | 使用者自己的私有雲端資料 | 依 `userEmail + tripId` 分開保存；不同使用者互不影響 |

## 五、維護規則

- 調整角色、管理按鈕、同步範圍或 Supabase RLS（資料列權限）時，必須同步更新本文件。
- 產品規格以本表為溝通基準；實際執行仍以 `permission.ts` 與 Supabase RLS 為準。
- 若表格與程式不一致，先修正不一致處，再進行發布。

## 六、V3.5.0 其他資訊卡片可見範圍與敏感資料模式（已定案、程式已補全）

適用於領隊／導遊、自駕／租車及一般其他資訊的每一張第二層卡片：

| 卡片設定 | guest | user | trip_editor（目前 Trip） | super_admin |
|---|---|---|---|---|
| 一般資訊（`allowed_roles is null`） | 可看 | 可看 | 可看、管理 | 可看、管理 |
| 敏感資料模式（`trip_editor`、`super_admin`） | 不可取得 | 不可取得 | 可看、管理 | 可看、管理 |

- 其他 Trip 的 `trip_editor` 對目前 Trip 視為 `user`，不得讀取受限制卡片。
- 未授權角色不顯示受限制卡片，也不顯示隱藏數量或存在提示。
- 一般資訊預設維持所有角色可查看；編輯畫面不提供額外可見範圍選項。
- 敏感資料由快捷入口建立或編輯，固定套用 `trip_editor` 與 `super_admin`；既有受限制卡片編輯時維持敏感模式。
- 前端顯示、Supabase RLS、Data API 與本機快取必須使用相同規則。
- 敏感快捷入口使用全中文角色文案：僅行程管理者可查看（已自動套用）；本行程參與者與系統管理者可查看；訪客與一般使用者不會看到此卡片。
- 本方案不新增敏感資料夾、第三層分類、一般資訊可見範圍選項、公開警語或儲存後權限預覽。
- 只有儲存敏感資料時顯示二次提醒；一般資訊儲存不顯示提醒，敏感判斷文案不直接放在編輯欄位。
- 模擬圖已完成並取得 Product Owner 確認，後續以本方案實作。
