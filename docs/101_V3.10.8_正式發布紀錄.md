### 歷史快取未通過：程式路徑與本機修正

- 已找到可解釋此失敗的邏輯缺陷：後端與前端先前部分依快取年齡是否達 24 小時（`isStale`）決定是否顯示 W09。若目的地日期／到達時間已過，但快取取得時間尚未滿 24 小時，或頁面重載後直接讀取已持久化的 `refresh_stopped` 快取，可能保留天氣值卻未持續顯示 W09「預報已超過有效期限，目前顯示的是歷史資料」。
- 本機修正分兩處：後端改依目的地日期／到達時間資格（`date_passed`／`arrival_passed`）選擇 W09；前端對 `ineligible` 且保留舊天氣資料的結果，以及重新載入後已標記 `refresh_stopped` 的快取，均固定使用 W09，不再以快取年齡決定是否顯示歷史資料提示。
- 已更新 `scripts/verify-v3101-weather-forecast.mjs`，讓回歸檢查涵蓋新的判斷條件。以下本機驗證均通過：`npm run verify:v3101-weather-forecast`、`npx --yes deno check supabase/functions/weather-forecast/index.ts`、完整 `npm run build`（包含天氣／時區回歸與 TypeScript）。
- 已在本機 DEV 以 6 小時前取得、`refresh_stopped=true`、目的地日期已過的合成快取驗證：頁面重載後仍保留舊天氣值，且顯示 W09「預報已超過有效期限，目前顯示的是歷史資料」。測試後已還原原本的 localStorage 天氣快取，沒有留下合成資料。
- 程式路徑與本機合成快取測試均支持這項修正；因尚未取得正式網站當時實際顯示的提示文字與快取時間，正式環境仍需用同類情境再次驗證。V3.10.9 程式與版本資訊已由 commit `2a88b8a` 提交並推送至 `develop`。2026-10-21 本次發布作業已獲使用者明確要求執行；合併與部署完成後，需在此補上實際 commit、workflow 與公開 smoke 證據。
