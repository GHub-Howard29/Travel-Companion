- [ ] Android 維持 V3.4.11 原生 Splash 流程，確認沒有重複圖示或順序改變。
- [ ] iOS 聚焦管理／編輯欄位及退出後維持正常寬度，不需兩指縮小，也不可左右移動。
- [ ] 回歸行程、共同／私人清單、其他資訊與旅程編輯視窗的焦點解除及水平溢出。

### 畫面模擬圖門檻

- [ ] 先製作「資訊可見範圍」新增／編輯卡片模擬圖，包含敏感資料警告、兩種可見範圍及受限制標示；Product Owner 確認後才可修改程式。
- [ ] 先製作 App 首頁分享入口模擬圖；入口位置確認後才可修改程式。

### 敏感資訊卡片權限

- [ ] 自駕／租車、領隊／導遊及一般其他資訊的每張第二層卡片可獨立設定可見範圍。
- [ ] 「所有使用者可查看」對 Guest、User、`trip_editor`、`super_admin` 顯示；現有卡片預設使用此設定。
- [ ] 「僅行程管理者可查看」只對目前 Trip 的 `trip_editor` 與 `super_admin` 顯示；未授權角色完全看不到卡片、數量或存在提示。
- [ ] 沿用 `allowed_roles`，同步完成前端過濾、Supabase RLS、Data API、複製／排序／編輯保留權限及多角色回歸測試。
- [ ] 卡片改為限制後，在未授權帳號下一次成功刷新時移除舊快取；登出後不得讓下一帳號讀取管理者敏感快取。
- [ ] 管理介面加入明確文案，要求訂房編號、訂位代碼、租車確認碼、私人電話、個資及敏感連結務必限制為僅行程管理者可查看。

### 分享、離線與待確認範圍

- [ ] App 分享只提供原生分享與複製固定首頁網址，不建立單一 Trip 分享連結。
- [ ] Guest 不提供離線行程內容；登入帳號的離線資料依帳號與權限隔離。
- [ ] 待 Product Owner 確認分享入口的確切位置。
- [ ] 待 Product Owner 確認敏感附件權限是否提前併入 V3.5.0；若納入必須同時完成 private Storage、Storage RLS、短效簽名網址與附件快取清除。
- [ ] 發布前最終確認 `FORCE_UPDATE`。
