## 3. 正式 Supabase Migration

正式專案：`travel-companion-db`（project ref `omnnmpcbcicpltkkobae`）。

成功套用以下兩筆 Migration：

| Migration | 正式 history name | 結果 |
|---|---|---|
| `20261103150000` | `v3110_trip_excel_create_rpc` | 已套用 |
| `20261106160000` | `v3110_trip_excel_request_recovery` | 已套用 |

部署前已以唯讀方式確認遠端缺少 Excel request registry 及兩個 Excel RPC；`private.tc_is_super_admin()`、`extensions.digest(bytea,text)` 與 pgcrypto 1.3 已存在。部署後唯讀核對：

- `private.tc_trip_excel_create_requests` 已建立，六個欄位皆為 NOT NULL。
- Request UUID primary key、payload SHA-256 格式 check、response JSON object check 均存在。
- Request registry 不含指向 `auth.users` 的外鍵；第二筆 migration 移除該 cascade FK，保留 user identity marker。
- `public.tc_create_trip_from_excel(...)` 與 `public.tc_get_trip_excel_create_request(uuid)` 均為 SECURITY DEFINER、`search_path=''`；ACL 僅授權 `authenticated` 與 owner postgres，未授權 anon／service_role。
- 遠端 migration history 已記錄兩筆正式版本。

### V3.10.12 租約 migration history 對齊說明

正式 DB 原有兩筆租約 migration IDs 為 `20261101170750`／`20261101170755`，而目前 repository 檔案使用 `20261101103000`／`20261101120000`。部署前由正式 migration history 取出原始 statements，與 repository 兩份 SQL 計算 SHA-256，逐筆完全一致；並以遠端 catalog 核對 table、constraints、indexes、RLS、Realtime publication、四個 RPC 的 SECURITY DEFINER、search_path 及 ACL。確認為同一 SQL 的不同版本時間戳，故未重跑租約 SQL。正式 history 中原有兩筆 IDs 保留。

本次只套用上述 V3.11.0 兩筆 Migration，未以整份 schema diff 或 `--include-all` 套用其他變更。
