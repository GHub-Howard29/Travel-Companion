# V3.9.2 正式建置環境隔離修正與發布紀錄

> 狀態：發布候選已完成，待正式部署與發布後 smoke
>
> 發布政策：必要更新；`minimumSupportedVersion: 3.9.2`、`forceUpdate: true`

## 問題與根因

V3.9.1 GitHub Pages 正式 bundle 誤含 `http://127.0.0.1:54321`。原因是本機回歸使用的 `.env.local` 仍會被 Vite production mode 載入，而 `npm run deploy` 的 `predeploy` 又會重新 build。手機上的 loopback 指向手機本身，因此 Supabase Auth／Trip 初始化無法完成，畫面持續停在載入中。

Android 額外檔案讀取權限提示目前沒有證據與此事故同源；V3.9.2 不修改 manifest、file handler 或附件權限，待取得完整提示內容後另案追查。

## 修正內容

- `scripts/build-production.mjs` 明確從正式 `.env`／程序環境取得 Supabase 設定，先驗證 HTTPS production origin，再呼叫 Vite；不採用 `.env.local`。
- `scripts/lib/production-environment.mjs` 集中處理環境檔解析、loopback 判定與正式環境驗證，錯誤訊息會說明接受的設定方式且不輸出 key。
- `vite.config.ts` 優先使用已驗證的程序環境值產生 CSP，避免 `loadEnv()` 讀入本機覆寫值。
- `verify:v392-production-environment` 覆蓋 HTTPS 成功、HTTP／loopback／帶路徑 URL 失敗，以及 CI 環境覆寫規則。
- `verify:browser-security` 會掃描 `dist` 的 HTML、JavaScript、CSS 與 JSON，拒絕本機 Supabase API URL，並確認 CSP 與 bundle 均含核准的 production origin。
- 版本升為 V3.9.2 並採必要更新，使受影響的 V3.9.1 使用者不能略過修正。
