## 對外更新提示

標題與政策文案由既有更新元件產生：

> 發現新版本
>
> 本次更新必須安裝才能繼續使用

本次更新內容：

- 每日行程新增拖曳、鍵盤及上下按鈕排序，儲存後可接著調整行程時間。
- 行程卡片可一次複製到同一旅程的多個其他 Day。

更新提示沿用既有資料警語：已儲存的旅程、清單、記帳與附件不會被清除；尚未儲存的表單內容會因重新載入遺失。必要更新只顯示「立即更新」，不提供關閉或「稍後更新」。

## 發布範圍

- `ItineraryItem` 新增可選穩定 ID；舊卡片於下一次行程寫入時補齊，全旅程維持唯一。
- 每日陣列位置成為唯一正式順序；畫面不再按到達時間強制重排，新增／複製仍依時間穩定插入，編輯既有時間不移動位置。
- 排序模式支援拖曳、鍵盤、上移／下移、本機草稿、取消與單次儲存；目的地改變時只清除失效路線快取並保留交通方式偏好。
- 管理者可將單張卡片一次複製到同旅程多個其他 Day；各副本使用新 ID，不複製相鄰交通欄位，不主動查詢路線。
- 本版不含 Supabase schema、RLS、Edge Function、Storage 或資料 migration，不需執行正式資料庫操作。

## Product Owner 手動發布（已完成）

1. 將 `origin/develop` 的 V3.8.0 候選合併至 `main`。若使用本機且可快轉，可執行：

   ```powershell
   git switch main
   git pull --ff-only origin main
   git merge --ff-only origin/develop
   ```

2. 在 `main` 再執行封版驗證：

   ```powershell
   npm run lint
   npm run build
   ```

3. 推送 `main`，建立並推送帶註解 Git 版本標籤：

   ```powershell
   git push origin main
   git tag -a v3.8.0 -m "Release V3.8.0"
   git push origin v3.8.0
   ```

4. 從 `main` 部署 GitHub Pages：

   ```powershell
   npm run deploy
   ```

5. 完成正式站檢查後切回開發分支：

   ```powershell
   git switch develop
   git merge --ff-only origin/main
   ```
