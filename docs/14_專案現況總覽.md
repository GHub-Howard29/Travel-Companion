# 專案現況總覽

> 本文件只記錄目前有效狀態；已發布歷史以《07_版本更新紀錄》為準，未完成工作以《09_待辦事項_TODO》為準。
>
> 最後更新：2026-09-10

## 正式版本

- 已發布 App 版本：V3.7.4；`main`、帶註解標籤 `v3.7.4`、GitHub Pages、正式 metadata、主程式資產與 `travel-route` Edge Function 均已完成發布驗證。
- 正式更新政策為一般更新，`minimumSupportedVersion: 3.6.4`、`forceUpdate: false`。
- V3.7.4 已修正地點搜尋的 CORS、錯誤解析、ES256 JWT 與新版 Supabase 金鑰相容問題；未變更資料庫或既有行程資料。

## 目前能力

- 以 Trip 為核心，提供每日行程、共同／私人清單、其他資訊、多人旅費帳本、附件、Excel 匯出及外幣換算。
- 每日行程支援到達／離開時間、相鄰地點交通方式／時間／距離、Google Maps 外部開啟，以及 V3.7.0 單次後續時間調整。
- React／TypeScript／Vite PWA；使用 localStorage、IndexedDB 與 Supabase 實作 Offline First、雲端同步及附件管理。
- 角色包含 Guest、User、`trip_editor`、`super_admin`；權限矩陣以《13_權限設定資料表》為準。
- Trip 主資料寫入使用遠端版本檢查，跨裝置版本衝突時不覆蓋遠端資料。

## 目前開發方向

- 下一個功能版為 V3.8.0「每日行程排序與跨日複製」。2026-09-10 盤點後已縮減為 MVP，避免重複建立 V3.7.0 的時間調整引擎。
- V3.8.0 以卡片穩定 ID 與每日陣列位置保存順序；不新增 `sortOrder`，不做全旅程資料遷移。
- 排序只保存新順序並清除失效路線，原到達／離開時間保留；需要時由使用者接續進入既有「調整時間」。
- 跨日複製支援同一旅程多選 Day、保留內容與時間、產生新 ID、依時間插入，不複製相鄰路線資訊。
- Product Owner 已於 2026-09-10 確認縮減版桌面／手機模擬圖；正式 UI 尚未開始修改，並依目前指示暫緩程式實作。
- 發布政策暫定必要更新，最終版本日期、metadata、tag 與部署仍須另行確認。

## 後續方向

- V3.8.1 只保留為排序後自動時間整合的候選改善，須先有實際使用需求。
- V3.9.0 卡片照片先做來源、授權、快取、效能、離線與成本可行性驗證，不視為已定案功能。
- V3.10.0 使用紀錄重新縮小範圍；原逐次明細、App 查詢頁、獨立角色與 TOTP 方案改列先前草案，須重新確認後才能實作。
- 預約紀錄、旅行日誌、保險資訊與 AI 助手維持未排程。

## 開發與發布邊界

- 所有新增或調整畫面必須先提供模擬圖，經 Product Owner 確認後才能修改程式。
- 未經 Product Owner 明確要求，不執行正式 Supabase migration、部署、合併、推送或建立 tag。
- 已發布 migration、版本 metadata、版本歷史與 Git tag 不回寫；問題一律以新版本向前修復。
- 修改完成後至少執行與風險相稱的純函式測試、TypeScript、lint、完整 build 與必要實機回歸。
