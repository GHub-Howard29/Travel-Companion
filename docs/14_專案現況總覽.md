## 目前開發目標

- **行程卡片天氣改為時間範圍預報（產品規格已定案，技術設計待補完，尚未實作）**：天氣是行程輔助資訊，依卡片時間決定全日預報、單一到達小時或到達～離開區段預報；區段預報只呈現單一摘要，新增獨立「區段預報快取」，上游小時粒度資料僅作為計算輸入，不提供逐小時列表。既有每日預報資料表與流程保持不動，並沿用現有 APP 首次檢查、每 6 小時固定排程、一般更新間隔、失敗冷卻、租約鎖定及重試機制。停止更新資格已明確整理：有到達時間的卡片在景點當地時間達到到達時間時停止；沒有到達時間的卡片，當地行程日期整天仍可依一般規則更新，直到當地日期進入隔天才停止。兩種規則都適用於全日與區段預報；區段離開時間不延長更新資格。共用快取只有在所有有效啟用天氣的引用卡片都失去資格後才停止更新。卡片天氣顯示採已定案的三層資訊分類，現有「⋯」狀態詳情及「還有 N 項提醒」收合行為不變；最後更新時間、Weathernews 與 Open-Meteo 來源／授權資料整合至「其他資訊」展開頁。天氣小 icon 放大兩倍。本次完成文件決策補充，未修改程式、migration、資料庫或部署。詳見《[79_天氣預報功能規格草案](79_天氣預報功能規格草案.md)》與《[95_天氣文案校稿與逐項確認紀錄](95_天氣文案校稿與逐項確認紀錄.md)》。

## 雙電腦測試資料交接（2026-10-29）

- 測試資料庫同步入口為 `npm run testdata:upload` 與 `npm run testdata:download`。方向只依共同 `last_synced_at` 及本地／Git `last_changed_at` 判斷：本地有基準後變更且 Git 無變更才可上傳；Git 有基準後變更且本地無變更才可下傳；雙邊變更一律停止，不覆蓋任一端。不得使用 checksum、內容指紋、revision／parent／applied-state 或 Git commit 時間判斷方向；Git 必須保留基本測試環境與必要 seed／fixture。
- 舊版 `testdata:handoff`、`testdata:import:all` 與 `testdata:handoff:publish` 命令已停用，不再作為任何一般同步路徑。fixture 版本號僅可作為舊資料／人工閱讀資訊，`package.json` 應用程式版本與測試資料同步無關。
- **最新時間戳同步規格已定案、尚未實作／驗收。** 後續需驗證 A／B 單邊上傳、單邊下傳、雙邊同時變更停止、時間戳異常停止及基本測試環境保留；舊版內容比較與 revision 驗證紀錄只供歷史追溯，現行規格見《[本機測試資料庫同步流程](83_本機測試資料庫同步流程.md)》。
