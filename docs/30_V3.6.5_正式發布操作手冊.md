# V3.6.5 正式發布操作手冊

> 狀態：已於 2026-09-08 完成 Git 版本標籤、GitHub Pages 部署與正式站登入 smoke；實體裝置待補驗
>
> 建立日期：2026-09-08
>
> 發布政策：一般更新；`minimumSupportedVersion: 3.6.4`、`forceUpdate: false`

## 一、發布範圍與判定

V3.6.5 只改善 PWA 更新或重新載入後重新顯示 App 的等待時間：

1. Session 與資料 ready 後立即移除靜態啟動畫面，不再等待 lazy 功能頁完成。
2. Session 確認後的同一次初始化共用完整 Trip 雲端快照，移除 metadata 與第一個 detail 的重複 Trip 查詢。

本版不是資料正確性、安全性或相容性的必要修正；不更新不會造成資料遺失。實測顯示資料 ready 平均改善約 27%，遮罩移除平均改善約 47%，因此保留本次低風險效能改善。

## 二、不需要執行的正式環境作業

- 沒有 Supabase schema、RLS、Function、Storage、Realtime publication 或資料轉換變更。
- 不需要 production database backup、migration、Edge Function 部署或 Google Cloud 設定變更。
- 不需要 V3.6.4 必要更新採用的 assets／metadata 兩階段相容窗口；V3.6.4 已符合最低支援版本，且 V3.6.5 為一般更新。

## 三、封版檢查

Codex 在建立 Git 版本標籤前必須確認：

- `main`、`develop`、`origin/main`、`origin/develop` 指向同一個封版提交。
- `package.json`、`package-lock.json`、`APP_VERSION` 與 `public/app-version.json` 均為 `3.6.5`。
- `PREVIOUS_RELEASE_VERSION = "3.6.4"`，且 V3.6.4 已加入版本歷史。
- `minimumSupportedVersion = "3.6.4"`、`forceUpdate = false`、`IS_MANDATORY_RELEASE = false`。
- 工作目錄乾淨，沒有 `.release`、暫時 worktree、量測檔或本機測試服務。
- `npm run lint`、`npm run build` 及 postbuild 瀏覽器安全驗證通過。

## 四、正式部署紀錄

2026-09-08 經 Product Owner 授權，由 Codex 在 `main` 執行：

```powershell
git switch main
git pull --ff-only origin main
npm run deploy
git switch develop
```

`npm run deploy` 會先重新執行完整 build，再將 `dist` 發布至 `gh-pages`。若 build 或推送失敗，停止操作並保留完整錯誤，不重複發布或自行修改版本資料。

本次完整 build、全部版本專項與 postbuild 瀏覽器安全驗證均通過，`gh-pages` 更新為 `d8c79d1e11a3f4d4ea874f3bd9ae2e2f01a18933`；GitHub Pages workflow `34146880726` 成功。部署後已切回 `develop`。

## 六、失敗與向前修復

- 部署前失敗：正式站仍為 V3.6.4，修正後重新完成封版驗證，不得移動或覆寫已推送的 Git 版本標籤。
- 部署後發現問題：V3.6.5 沒有資料庫變更，既有資料不需回復；依發布規則建立 V3.6.6 向前修復，不回寫 V3.6.5 版本歷史或 metadata。
- 不得把 Android、iOS 或兩台實體裝置未執行的項目補記為通過。
