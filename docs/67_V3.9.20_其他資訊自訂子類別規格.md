# V3.9.20 其他資訊自訂子類別規格

> 狀態：2026-09-30 Product Owner 已完成 UI 與互動規則定案；本階段只整理文件與編列版本，尚未實作、測試、升版、commit、push、merge、tag 或部署。
>
> 版本決策：本功能插入為 V3.9.20；原 V3.9.20「排序後續時間重算與調整時間整合評估」順延為 V3.9.21。

## 目標

將「其他資訊」目前寫死的固定子類別改為可依每一趟 Trip 需求管理的子類別。使用者可新增、改名、排序與隱藏子類別，例如將本次行程用不到的「簽證」改名為「天氣」，或新增「御朱印」。

本版只處理「其他資訊」子類別管理與顯示排列，不合併 V3.9.21 的排序後續時間重算／調整時間功能。

## 主畫面入口

1. 「其他資訊」上方維持現有子類別按鈕區。
2. 現行提示欄位文字「其他資訊管理」維持不變，直接把這個既有區塊做為子類別管理入口。
3. 不另新增「管理子類別」文案。
4. 「其他資訊管理」入口可加入右箭頭或設定圖示，讓使用者知道可點入，但不改變原本文案。
5. 「新增資訊」表單與一般／敏感資料切換維持現有位置與主要操作流程。

## 其他資訊管理畫面

管理畫面沿用標題「其他資訊管理」，提供：

- 新增子類別。
- 修改子類別名稱。
- 拖曳調整使用者順序。
- 顯示／隱藏子類別。
- 自動排列。
- 恢復預設。
- 排列預覽。
- 完成並返回。

### 子類別列表

每一列至少包含：

- 拖曳把手：手動調整順序。
- 資料夾圖示與子類別名稱。
- 該子類別目前筆數。
- 鉛筆圖示：改名。
- 眼睛圖示：目前顯示。
- 斜線眼睛圖示：目前隱藏。

隱藏只影響「其他資訊」主畫面的子類別按鈕是否顯示，不得刪除該子類別或其既有資料。被隱藏的子類別仍保留在「其他資訊管理」清單內，讓使用者可再次開啟。

### 顯示／隱藏即時回饋

1. 顯示中使用一般眼睛圖示。
2. 點擊後切換成斜線眼睛，表示已隱藏。
3. 隱藏時立即短暫浮現「已隱藏」。
4. 再次點擊後恢復一般眼睛，立即短暫浮現「已顯示」。
5. 狀態提示約 1 秒後自動消失。
6. 圖示必須先立即反映新狀態，不等待提示消失。
7. 提示位置以不遮住目前操作列為原則，建議使用畫面中下方 toast。
8. 顯示／隱藏按鈕需提供可辨識的 aria-label，不能只依圖示讓輔助科技判斷狀態。

## 自動排列

### 操作方式

- 子類別列表提供「自動排列」操作。
- 執行後先更新排列預覽與管理清單順序，實際保存時機依實作階段再確認，但不得在未確認前破壞既有資料。
- 自動排列是協助整理顯示順序，不取代使用者後續拖曳調整。

### 定案排列規則

1. 每列最多顯示 3 個子類別。
2. 短名稱應優先組合在同一列，避免長名稱先佔用剩餘寬度造成不必要空白。
3. 換行後，候選子類別以少字元到多字元優先排列。
4. 若下一個較長名稱無法放進該列剩餘寬度，直接換到下一列，不強制壓縮字寬。
5. 優先維持文字可讀性，不為湊滿三個而縮小字體、壓縮字距或讓文字互相重疊。
6. 子類別按鈕可依內容使用不同寬度；「一列 3 個」是上限，不是固定三等分欄位。
7. 自動排列後仍允許使用者手動拖曳改變順序。

### UI 驗收範例

短名稱可排列為：

- 第 1 列：景點、機票、飯店
- 第 2 列：交通、其他、御朱印
- 第 3 列：天氣與降雨、購票與通關
- 第 4 列：自駕取車／還車

此範例用來驗證「短名稱優先填滿可用列、長名稱放不下才換行」；實際寬度仍以裝置 viewport、字型與按鈕 padding 的量測結果為準。

## 自動排列規則說明

1. 「自動排列規則」在管理畫面預設收合，避免長文案佔用手機畫面。
2. 收合時只顯示簡短標題，例如「ⓘ 自動排列規則」與展開箭頭。
3. 點擊後才展開完整規則，再點一次收合。
4. 展開控制使用真實 button，並提供 aria-expanded 與對應內容區域。
5. 完整文案至少說明：
   - 每列最多 3 個子類別。
   - 換行後優先由少字元排到多字元。
   - 長名稱放不下時直接換行。
   - 不壓縮字寬，優先維持可讀性。

## 新增與改名

- 使用者可新增自訂子類別，例如「御朱印」。
- 使用者可將既有子類別改名，例如「簽證」改為「天氣」。
- 改名不得使既有資料遺失。
- 「其他」保留為可用分類；是否允許改名／隱藏與是否需要至少保留一個可見分類，實作前應由資料契約檢查決定，若現有資料結構有特殊保留值不得直接破壞。
- 名稱空白、重複、過長、特殊字元與最大子類別數量需在實作前依現有資料結構訂出明確驗證規則。

## 新行程共同基底與行程性質差異

### 共同基底

1. V3.9.20 不建立兩套完整 Trip 模板；新 Trip 沿用同一套共同功能與共同資料結構。
2. 每日行程、共同確認清單、私人確認清單、其他資訊、旅費記帳本、外幣換算、參與者、權限、Offline First、同步、照片、路線資料與 Change Journal 等均維持共同設計，不因 `guided`／`selfGuided` 產生兩套版本。
3. 「其他資訊」只保留一套系統共同預設分類：景點、機票、飯店、交通、票券、保險、簽證、美食、購物、其他。
4. 新 Trip 的其他資訊分類不得直接複製受保護 seed 行程 `free-travel-2026-01` 或 `group-tour-2026-10`；兩個 seed 行程只保留為示範／歷史種子資料。
5. 建立 Trip 時，將共同預設分類複製成該 Trip 專屬分類設定；建立後的新增、改名、排序、顯示／隱藏只影響該 Trip。

### TripMode 差異

`TripMode` 只控制目前實際存在的差異，不衍生兩套完整模板：

- `guided`
  - 頁首行程性質顯示「跟團」。
  - 專屬入口顯示「領隊導遊聯絡資訊」。
  - 使用 `special-info-guided` 專屬資料區。
  - 預設欄位：領隊、電話、導遊、電話、集合提醒。
- `selfGuided`
  - 頁首行程性質顯示「自助 / 自駕」。
  - 專屬入口顯示「自駕租車須知」／「自駕租車資訊」。
  - 使用 `special-info-self-guided` 專屬資料區。
  - 預設欄位：租車公司、取車地點、取車時間、還車地點、還車時間、注意事項。

若未來新增新的行程性質差異，只擴充 TripMode 專屬設定，不複製其他共同功能。

### 建立後切換行程性質

1. 使用者修改 Trip 行程性質時，只切換 TripMode 專屬顯示與專屬資訊區；不得自動重建或覆蓋其他資訊分類、每日行程、帳本、換匯、清單或其他共同資料。
2. 已存在的其他資訊分類名稱、順序、顯示狀態與內容全部保留。
3. 專屬資訊切換時不得誤刪另一模式既有資料；實作時需確認現有資料契約後採非破壞性保存／切換策略。

### 恢復預設

1. 「恢復預設」只針對共同的其他資訊預設分類，不區分 `guided`／`selfGuided`。
2. 恢復預設須先顯示確認，不得直接覆寫。
3. 對系統原生分類，可恢復共同預設定義的顯示名稱、順序與顯示／隱藏狀態。
4. 使用者自行新增的分類與其中既有資料不得因「恢復預設」被刪除；自訂分類應保留，必要時排列在系統分類之後。
5. 恢復預設不得搬移、刪除或重分類任何既有其他資訊卡片；若分類穩定 ID／資料契約發生衝突，應停止並要求人工處理，而不是猜測對應關係。

## 資料與同步邊界

- 自訂子類別應屬於目前 Trip，不應無條件影響其他 Trip。
- 系統共同預設分類只負責建立新 Trip 與「恢復預設」的來源，不作為既有 Trip 的即時繼承來源。
- 本版不得因 UI 改造刪除、重建或重分類既有「其他資訊」資料。
- 分類需使用穩定 ID／key 與可修改顯示名稱分離；「改名」只能改顯示名稱，不得改變既有 OtherInfoItem 的分類歸屬。
- 需沿用既有其他資訊的 Offline First、同步、權限與敏感資料安全邊界。
- 是否需要 Supabase schema／migration 必須在實作前先檢查現有模型；若 Trip 分類設定需要新增持久化欄位，必須使用向前 migration，不回寫既有已發布 migration。

## 驗收條件

### 手機 UI

- 390×844 寬度下，短名稱能在同列合理放入最多 3 個。
- 長名稱不重疊、不裁切重要文字、不造成水平捲動。
- 自動排列後可得到上述短名稱優先的驗收範例。
- 「其他資訊管理」入口沿用原文案，不新增重複入口。
- 排列規則預設收合，展開／收合狀態與無障礙屬性正確。

### 管理功能

- 新增子類別後可立即在預覽與清單看到。
- 改名後既有資料仍歸屬原分類。
- 拖曳排序可調整使用者順序。
- 自動排列符合短字元優先與每列最多 3 個規則。
- 隱藏後主畫面不顯示，但管理清單與既有資料仍存在。
- 顯示／隱藏圖示正確切換，並顯示約 1 秒的「已隱藏／已顯示」toast。
- 恢復預設使用共同的其他資訊系統預設分類，且不得刪除使用者自訂分類或其中既有資料。
- 新建 `selfGuided` 與 `guided` Trip 均由同一套共同其他資訊預設分類建立，且不複製兩個受保護 seed 行程的其他資訊內容。
- 建立完成後修改行程性質，只切換 TripMode 專屬資訊，不會自動覆蓋其他資訊分類或其他共同功能資料。

### 回歸

- 一般資訊／敏感資料新增與編輯維持。
- 其他資訊既有同步、離線、權限、連結與敏感資料規則不回歸。
- 桌面與手機版均需驗證。
- 完整 build、TypeScript、lint、browser-security、相關 regression 與必要的實機 RC 通過後才可發布。
