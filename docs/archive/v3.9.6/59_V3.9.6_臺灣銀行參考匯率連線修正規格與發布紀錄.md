## 對外更新提示

> 修正臺灣銀行牌告參考匯率無法連線載入的問題。

## 問題與根本原因

1. **問題現象**：
   * 使用者於「外幣換算」功能點擊「載入最新參考匯率」時，介面報錯：「無法載入臺灣銀行參考匯率（無法連線至匯率服務，可能是網路連線或臺灣銀行網站暫時異常）。」
2. **根本原因分析**：
   * **CORS 預檢標頭阻擋**：自 V3.6.4 起，前端全域 Supabase 客戶端一律附加 `x-travel-companion-client-id` 客製標頭。然而 `taiwan-bank-exchange-rate` Edge Function 自 V3.3.0 建立後未曾更新，使用了通用套件的預設 `corsHeaders`，其 `Access-Control-Allow-Headers` 未將 `x-travel-companion-client-id` 列入白名單。瀏覽器發送跨域 OPTIONS preflight 請求時，因標頭不合規範直接中斷實際 POST 請求，前端捕捉到 `TypeError: Failed to fetch`。
   * **閘道 JWT 驗證風險**：`supabase/config.toml` 中將該函式設為 `verify_jwt = true`。臺銀參考匯率為公開牌告資訊，不含使用者資料或私有資料表操作；若啟用閘道層 JWT 驗證，未登入訪客（Guest）或非對稱 ES256 Token 可能遭到平台 HTTP 401 攔截。

## 修正內容

1. **Edge Function CORS 宣告明確化**：
   * 在 `supabase/functions/taiwan-bank-exchange-rate/index.ts` 中，比照 `travel-route` 明確宣告 CORS 白名單：
     ```ts
     const corsHeaders = {
       "Access-Control-Allow-Origin": "*",
       "Access-Control-Allow-Headers":
         "authorization, apikey, content-type, x-client-info, x-travel-companion-client-id",
       "Access-Control-Allow-Methods": "POST, OPTIONS",
     };
     ```
2. **關閉函式閘道強制 JWT 驗證**：
   * 在 `supabase/config.toml` 中，將 `[functions.taiwan-bank-exchange-rate]` 之 `verify_jwt` 設為 `false`，由函式自行處理公開請求。
3. **新增防退化驗證腳本**：
   * 新增 `scripts/verify-taiwan-bank-exchange-rate.mjs`，檢查該 Edge Function 之 CORS 白名單與 `config.toml` 設定，並加入 `npm run build` 驗證鏈。
4. **版本計畫順延決策**：
   * 本修復作為獨立 Patch 版本 V3.9.6 上線。
   * 原定路線圖依序順延：
