# V3.9.1 跨日複製四碼時間輸入修正規格

- 狀態：已排入 V3.9.1；2026-09-16 已完成本機實作、自動驗證，以及登入管理者桌面與 390×844 互動驗證。
- 類型：既有跨日複製時間欄位的前端可用性修正；不調整 Trip 資料格式、Supabase、RLS、角色、照片功能或外部 API。

## 問題

跨日複製的「抵達時間」與「離開時間」目前以 `inputMode="numeric"` 顯示數字鍵盤，但驗證只接受含半形或全形冒號的 `H:MM`／`HH:MM`。在行動裝置無法方便輸入冒號時，連續輸入 `1400` 會被判為無效，無法完成複製。

## 已排定行為

- 欄位採文字輸入搭配數字鍵盤（`type="text"`、`inputMode="numeric"`），避免原生數字輸入限制冒號；UI 視覺配置依本規格已核准 mock 執行。
- 兩個跨日複製時間欄位均接受連續四碼數字；輸入完成第四碼時，自動格式化為 `HH:MM`。例如 `1400` 變為 `14:00`、`0930` 變為 `09:30`。
- 既有半形／全形冒號輸入與儲存前正規化為 `HH:MM` 的行為保持相容。
- 每次輸入或貼上後，若欄位恰為四個半形或全形數字，先正規化數字並檢查時分有效性；有效才格式化為 `HH:MM`。含半形／全形冒號的輸入維持既有相容處理，不當作四碼重排。
- 自動格式化後游標移至末端；使用者刪除或修改已格式化時間時，不自動補回冒號，直到再次得到完整有效四碼或提交驗證。IME 組字期間不得格式化，等組字結束後才判斷。
- `14000`、`1 400`、`14-00` 等非恰為四碼的輸入不猜測處理，保留欄位內容並交既有驗證。
- 只有恰為四碼、且時分有效的數字可自動格式化；`2400`、`2460` 等無效值維持欄位內容，並在提交時顯示對應格式警告，不得自動改成其他時間。
- 少於四碼的輸入不猜測為時間，仍由既有必填／格式驗證處理；不新增跨午夜支援。
- 自動格式化後，既有「離開早於抵達」檢核、單日／多日複製、排序插入、一次 Trip 寫入與失敗不部分寫入規則均不得改變。
- 欄位輸入中、離焦或剛好四碼無效時均不顯示錯誤跳窗；有效四碼自動格式化後清除該欄位暫存錯誤。只有按下複製時才執行完整必填、格式與抵達／離開先後檢核並顯示警告。
- 錯誤訊息必須依原因提供可操作的正確格式：空白為「請輸入抵達／離開時間；可輸入 1400 或 14:00。」；少於四碼或格式混合為「時間請輸入四碼，例如 0930，或使用 H:MM／HH:MM，例如 9:30 或 09:30。」；四碼時分無效為「時間需介於 00:00 至 23:59；例如 1400 或 14:00。」；離開早於抵達為「離開時間需等於或晚於抵達時間；跨午夜請分開建立行程。」。對外說明的可接受格式為 `H:MM`、`HH:MM`、`HHMM`，仍相容全形數字與全形冒號。
- 桌面與 390×844 手機皆維持抵達／離開兩欄並列；欄位上方固定顯示「可輸入 1400 或 14:00。」，欄位下方不顯示錯誤文字。按下複製仍有錯誤時，阻止寫入並顯示可關閉的「請檢查時間格式」警告跳窗，內容使用前項對應錯誤說明，提供「知道了」按鈕。抵達與離開同時錯誤時，跳窗必須一次條列所有錯誤及各自正確格式／修正方式；不得只先顯示第一項、修正後再跳下一項。關閉後焦點移至第一個錯誤欄位。螢幕閱讀器只在提交時宣告警告，不得在每次按鍵或離焦時重複宣告。
- 警告跳窗必須使用 `role="alertdialog"`，提供可辨識標題與錯誤內容描述；開啟時焦點置於「知道了」，Tab 焦點不得跑到被遮住的跨日複製對話框。按 Escape 與按「知道了」效果相同：關閉警告並回到第一個錯誤欄位。跳窗開啟期間不得關閉外層對話框或遺失已填時間／已選 Day；行動裝置套用相同語意與焦點規則，不得使用原生 `alert()`。
