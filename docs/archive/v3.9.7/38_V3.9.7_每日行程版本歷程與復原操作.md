# V3.9.7 每日行程版本歷程與復原操作

## 範圍

- 歷程只保存 `trips.content.daysData` 中被修改 Day 的變更前卡片陣列。
- 同一 Trip、同一 Day 每個整點區間最多保存第一份變更前快照，最近保留 30 份。
- 歷程位於 `private.itinerary_day_history`，瀏覽器角色與 `service_role` 均無讀取權限。
- 工具只接受當次提供的 `TRAVEL_COMPANION_DATABASE_URL`，不會把連線字串寫入檔案。

## 事故前歷程不存在時的離線救援

可攜工具原始碼位於 `tools/offline-itinerary-rescue`，以 Chromium 官方 Local Storage LevelDB 格式唯讀解析 Chrome／Edge 設定檔。它不啟動 PWA、不使用 Supabase，也沒有網路模組。

建立 Windows x64 可攜 ZIP：

```powershell
npm ci --prefix tools/offline-itinerary-rescue --ignore-scripts
node tools/offline-itinerary-rescue/verify-rescue.mjs
node tools/offline-itinerary-rescue/build-portable.mjs
```

產物位於 `.release/TravelCompanion-Itinerary-Rescue-v1.0.0-win-x64.zip`。在目標電腦執行前必須中斷網路，並完全關閉 PWA、Chrome 與 Edge。工具先將 LevelDB 複製到系統暫存資料夾並確認來源指紋在複製前後一致，只輸出目標 Trip 的 `daysData`、摘要、時間戳與 SHA-256，不輸出登入權杖或其他網站資料。

## 部署後驗證

套用 migration 後，以資料庫管理連線執行：

```text
docs/sql/032_v397_itinerary_day_history_validation.sql
```

所有查詢均須回傳 `true`。

## 唯讀列出歷程與差異

```powershell
$env:TRAVEL_COMPANION_DATABASE_URL = '<當次核准的資料庫連線字串>'
npm run itinerary:history -- list --trip group-tour-2026-10 --day 1
```

輸出包含歷程 ID、快照及目前版本時間、卡片數、標題、寫入者／來源 client ID，以及相對目前 Day 的新增、缺少與內容變更摘要。

## 單一 Day 復原

1. 先執行 `list`，人工核對 Trip、Day、歷程時間、標題與差異。
2. 取得輸出的 `currentUpdatedAt`，在正式寫入前再次讀取並確認未變更。
3. 精確輸入二次確認字串：

```powershell
npm run itinerary:history -- restore --trip group-tour-2026-10 --day 1 --history-id 123 --expected-updated-at 2026-09-24T00:00:00.000000+00:00 --confirm "RESTORE group-tour-2026-10 DAY 1 FROM 123"
```

還原在單一交易內以 `updated_at` 樂觀鎖定，只替換指定 Day；版本歷程觸發器會先保存被替換內容，既有 revision 觸發器則通知其他裝置重新載入。

## 停止條件

- 備份／歷程來源無法證明是正確內容。
- `currentUpdatedAt` 已改變。
- 差異包含預期範圍以外的 Trip 或 Day。
- 尚未取得該次正式資料庫寫入授權。
