# V3.9.21 PWA 更新後重新載入白畫面修復規格

> 狀態：2026-10-01 已完成實作、production build、回歸驗證與 RC 部署，並依 Product Owner 決策進入正式發布收尾。V3.9.20 → V3.9.21 的第一次升級仍由 V3.9.20 舊更新程式執行，因此無法用這一跳完整驗證 V3.9.21 新接管邏輯；真正的跨版本實機驗證延後至 V3.9.21 → V3.9.22 RC。

## 問題現象

Android PWA 更新流程中：

1. 舊版偵測到新版。
2. 顯示等待新版本接管。
3. 等待一段時間後提示「重新載入套用新版」。
4. 使用者按下重新載入。
5. 畫面可能變成空白，App 無法直接進入。
6. 關閉 PWA 並重新啟動後恢復正常。
7. 重啟後顯示新版版本號，可正常進入程式。

## 已確認邊界

- 新版資產本身可正常啟動。
- 關閉並重新開啟後可正常進入新版，表示 build／部署內容本身不是持續性白畫面。
- 問題集中在舊 Service Worker → 新 Service Worker 接管與 reload 的切換時序。
- V3.9.20 不在正式發布前臨時混入此修正，避免擴大已通過 RC 的範圍。

## V3.9.21 目標

修正 PWA 更新接管流程，使使用者在收到「重新載入套用新版」後：

- 按重新載入即可直接進入新版。
- 不出現空白畫面。
- 不需要手動關閉／重啟 App。
- 更新完成後版本號正確。
- 冷啟動與既有 Offline First 行為不回歸。

## 優先檢查範圍

實作前先檢查目前：

- 新版偵測流程。
- Service Worker waiting／skipWaiting。
- controllerchange 監聽。
- 新 Service Worker 接管完成條件。
- reload 的實際觸發時機。
- reload 前後 active controller 是否一致。
- Android Chrome／PWA visual lifecycle 與背景頁面節流。
- update prompt 是否可能重複觸發 reload。
- PWA cache 與 HTML／JS navigation 是否可能在接管瞬間短暫不一致。

不得只用延遲幾秒的方式掩蓋問題；應先找出接管完成與 reload 的可靠邊界。

## 驗收條件

V3.9.21 發布前已完成：

1. Service Worker handoff 靜態契約驗證。
2. TypeScript、完整 production build、既有 regression、PWA 產物與 browser-security 驗證通過。
3. RC 已部署，V3.9.21 版本 metadata 與新版程式可正常產生。

跨版本 Android PWA 實機驗證延後至 V3.9.22 RC，並由已執行 V3.9.21 新更新程式的客戶端驗證。

V3.9.22 RC1 實測進一步發現：若遠端 Trip revision 已更新、但目前裝置尚未同步，使用者此時直接執行 App 更新，可能卡在 Service Worker 等待接管／重新下載；等 Trip 資料先同步完成並冷啟動後，新版才正常進入。RC2 因此補強更新邊界：

- App 更新按鈕先進入「正在同步行程資料」，完成 workspace reconciliation 與目前 Trip reload 後才開始版本 metadata／Service Worker 更新。
- 資料 preflight 失敗時停止程式更新，不進行 Service Worker 接管，且不覆蓋目前資料。
- Workbox onNeedReload 不再自行 reload；實際 reload 僅由 useAppUpdate 在 handoff 驗證完成後控制。
- App 更新提示存在時，Trip revision reload 提示暫不並行顯示，避免兩條 reload 流程同時由使用者觸發。

RC2 驗收邊界：

- V3.9.21 → V3.9.22 的升級仍由 V3.9.21 程式執行，因此不能用這一跳驗證 RC2 新增的「更新前同步」流程；RC1 已證實這個舊流程仍可能與尚未同步的遠端 Trip revision 競態。
- RC2 可立即驗證雙欄位時間調整、資料 preflight／單一 reload owner 的靜態與整合回歸，以及 RC2 程式本身正常啟動。
- 新的 App 更新 preflight 必須由已經執行 V3.9.22 RC2 程式的客戶端，在 V3.9.22 → 下一版本更新時做真正端到端實機驗證。

下一版本更新時的實機複驗條件：

1. 先在另一裝置建立遠端 Trip revision，讓 V3.9.22 測試裝置尚未同步，再按 App 更新。
2. 應先看到「正在同步行程資料」，完成後才進入新版下載／接管；不得因遠端 revision 卡在重複下載。
3. 更新中按鈕不得跳回可再次點擊的更新狀態。
4. 若出現「重新載入套用新版」，按下後直接進入新版，不出現白畫面。
5. 不需要手動關閉／重新啟動 PWA。
6. 更新提示不重複循環。
7. 關閉後再次冷啟動正常。
8. 離線啟動與既有 PWA cache 行為不回歸。

## 版本順延

原 V3.9.21「排序後續時間重算與調整時間整合」順延為 **V3.9.22**，功能範圍與已定案產品規則不變。
