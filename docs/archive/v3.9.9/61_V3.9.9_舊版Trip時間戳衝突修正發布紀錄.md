# V3.9.9 舊版 Trip 時間戳衝突修正發布紀錄

> 狀態：已發布（2026-09-24）  
> 類型：Patch／一般更新

## 修正範圍

- 修復 V3.9.8 前既有快取已將本機寫入時間誤當成雲端版本時間，造成卡片儲存持續誤判跨裝置衝突。
- 第一次樂觀鎖失敗後只讀取一次最新雲端 Trip；只有 Trip 本體一致、差異限於獨立同步資料時，才以最新雲端時間戳重試一次。
- `daysData`、行程基本資料或側邊欄等 Trip 本體若真的不同，維持衝突阻擋，不自動覆蓋。
- 本版沒有 migration、Edge Function、RLS、Storage 或正式資料內容變更。

## 已完成驗證

- `npm run regression:local:full` 通過本機 Supabase grants、合成管理者登入、Trip 載入、Edge 輸入防線、完整 build、TypeScript 與正式產物瀏覽器安全檢查。
- 新增 `verify:v398-trip-version-recovery` 回歸，覆蓋舊時間戳自癒、只重試一次、真正衝突維持保護及非版本錯誤不額外讀取雲端。
- synthetic loopback 瀏覽器實測將 `cloudUpdatedAt` 設為舊值後，卡片可正常儲存且不再顯示「行程資料已在其他裝置更新」；測試標題已還原。
- 照片選擇視窗的一字搜尋禁用、390×844 無水平溢位與控制項可達性通過；未送出 Wikimedia 外部請求。
- Supabase `migration list --linked` 與 `db push --linked --dry-run --skip-vault` 確認正式資料庫同步，沒有待套用 migration。
- `main` 合併提交：`88212d8`；annotated tag：`v3.9.9`；GitHub Pages 部署提交：`817257c`。
- 公開首頁與附不快取查詢的 `app-version.json?release=v3.9.9` 均回應 HTTP 200，版本檔內容為 3.9.9。

## 資料邊界與待補驗

- 瀏覽器回歸使用 `127.0.0.1` 本機 Supabase、固定合成帳號與 fixture，不讀寫正式 Trip；正式環境只執行 migration 清單與 dry-run。
- Android／iOS 實機仍需以 V3.9.8 前既有快取確認自癒，並以第二台裝置真正修改 Trip 本體時確認衝突阻擋。
