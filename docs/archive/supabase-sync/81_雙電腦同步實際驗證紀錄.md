## 2026-10-29 雙電腦標準同步入口驗收

兩台電腦均使用 `npm run db:sync:local` 作為本機標準同步入口。流程包含 loopback 端點確認、pending migrations、fixture handoff 偵測與驗證、版本化 fixture 匯入、regression prepare 與 verify。入口不執行 reset、不清除資料、不自動 pull／commit／push。

當時紀錄確認公司與家用電腦均已在 `develop` 執行該入口，回報 `synchronized: true` 且標準本機回歸驗證通過；家用電腦 fixture 核心資料與版本控制 fixture 相符。這只證明兩台電腦各自的標準 migration／fixture 匯入／回歸入口通過，不代表真正 A→B→A 雙向交接、兩台各自新增資料的合併，或 `released`／`archived` 生命週期端到端驗收。

## 尚待實證的範圍

- 實際操作產生新的資料庫資料後，兩端對該次同步版本的確認。
- `testdata:handoff:publish` 在真實 fixture 變更情境下的自動 commit／push 行為。
- 真正 A→B→A 雙向資料交接、兩端各自新增不同資料時的合併與衝突處理端到端驗證。
- `released`／`archived`／`deleted` 生命週期端到端驗收。

以上項目待真實資料事件發生時依實際證據補驗，不刻意製造測試資料。遇到同鍵不同內容時，現行匯入會中止並要求人工處理，不會自動合併或採 last-write-wins。
