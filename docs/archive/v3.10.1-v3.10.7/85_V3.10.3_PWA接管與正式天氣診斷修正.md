# V3.10.3 PWA 接管與正式天氣診斷修正

> 整理日期：2026-10-18
> 狀態：V3.10.3 已完成 push、合併、部署與發布後 smoke；正式真實天氣單卡端到端補驗待合資格資料出現。

## 1. 修正目的

V3.10.2 發布後仍觀察到兩項跨版本問題：

- PWA 可能顯示等待新版接管，接著進入重試更新；重啟 App 後才顯示已更新，代表舊頁面曾在新版 worker active 時過早宣告成功，卻未確認新版 controller 已接管。
- 天氣在本機可取得，但正式 App 仍顯示暫時無法取得。現有錯誤被前端收斂成泛化訊息，無法區分正式鏈路的授權、Google Places 座標、Open-Meteo、租約、天氣快取或 UI 階段。

## 2. V3.10.3 程式修正

### PWA 更新接管

- `active` worker 不等於目前頁面已由新版接管；若 `navigator.serviceWorker.controller` 尚未與 active worker 對齊，只能進入 `ready-to-reload`，由使用者按一次「重新載入套用新版」。
- 未確認 controller 接管前，不直接 reload、不寫入已更新版本、不重複觸發網路更新。
- 只有 controller 已確認接管，才允許自動重新載入；逾時訊息改為引導套用新版，不再引導連續重試。
- 專項契約驗證固定納入 `verify:v3924-update-handoff` 與 `verify:v3913-update-race`。

### 正式天氣診斷

- Edge Function 與前端僅記錄安全錯誤碼及 opaque trace ID，不輸出 API key、Auth token、Trip／地點識別值、原始 provider body 或 secret。
- 回應診斷碼區分授權、座標、上游天氣、租約／RPC、快取寫入與其他階段，供正式 log 對照。
- 本機成功只代表本機設定與測試資料路徑通過；正式驗證必須有合資格的真實行程卡片，確認 Google Places → 座標快取 → Open-Meteo → 天氣快取 → UI 的完整鏈路。
- 空結果、只有 OPTIONS／未授權邊界，或只有靜態檢查，均不得宣稱正式單卡天氣成功。

## 3. 安全與資料邊界

- 本版本不新增 migration、不改正式資料、不輪替 secrets；僅部署已驗證的 `weather-forecast` Edge Function 程式碼，不執行正式環境資料寫入。
- API keys 與其他 secrets 應留在 Supabase Edge Function secret store；資料庫只保存其既定的業務資料與快取，不把 secret 值寫入 App、版本 metadata 或文件。
- 生產診斷只保留必要的安全錯誤碼與 trace ID；若需追查，應以 Supabase／Edge Function 的受控 log 查詢，不把敏感值複製到 commit、issue 或聊天內容。
