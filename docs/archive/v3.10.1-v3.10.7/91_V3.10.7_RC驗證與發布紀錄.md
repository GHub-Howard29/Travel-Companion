## 7. 2026-10-19 根因修正與實機驗收

- **實機驗收**：使用者在 V3.10.7 測試版新增三個地點（皆為新座標），逐一驗證 D1–D5；三個地點的 15 個地點日期全部成功取得天氣。此結果由使用者實機回報，記錄為 RC 多日天氣回寫阻擋解除的驗收證據。
- **根因**：`tc_weather_release_lease` 將座標快取的 double precision 與 JSONB payload 轉回的 double precision 做完全相等比較。真實座標如 `22.5749333, 120.3471544` 經 JSONB 數值序列化／解析後可能產生數個 ULP 的微小差異；SQL 因此回傳 `false`，呼叫端將成功回寫誤判為 `WEATHER_CACHE_WRITE_FAILED`。JavaScript 端的比較無法揭露 SQL JSONB 往返差異。
- **修正**：新增 `supabase/migrations/20261019180000_v3107_weather_release_precision_fix.sql`，將座標比較改為 `1e-7` 度容差，並保留座標列先鎖定、lease token 驗證、座標狀態與 TTL 重驗。大於容差的實際座標差異仍會 fail closed。
- **本機驗證**：`scripts/test-weather-release-lease.sql` 使用精度敏感的真實座標測試；正常回寫成功，座標不匹配、lease 被替換、座標狀態改變及 TTL 過期等拒絕條件仍通過。`npm run verify:v3101-weather-forecast` 與 `git diff --check` 通過。
- **正式資料庫部署（2026-10-19）**：執行 `npx supabase db push --linked --dry-run` 確認遠端只待套用 `20261019180000_v3107_weather_release_precision_fix.sql`；隨後套用成功，並以 `npx supabase migration list --linked` 核對 Local／Remote 均列出 `20261019180000`。
- **正式 Edge Function 部署（2026-10-19）**：執行 `npx supabase functions deploy weather-forecast --project-ref omnnmpcbcicpltkkobae` 成功；部署後 `npx supabase functions list` 顯示 `weather-forecast` ACTIVE version 12（部署前 version 11）。
- **發布前界線（歷史紀錄）**：該階段只更新正式資料庫 migration 與 `weather-forecast` Edge Function；當時尚未更新 GitHub Pages、未建立正式 tag、未合併 `main`。正式發布結果已在第 8 節補齊。
