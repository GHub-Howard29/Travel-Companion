> 建立日期：2026-10-20
> 狀態：**2026-10-20 依使用者指示終止本輪評估；三站公開證據與官方條款已完成第一輪比較，人工互動、清除 Cookie、跨地區重開及部分景點／同名地點未完整驗證，相關缺口封存不再追蹤。**
> 目的：保存本輪三個候選網站的證據、比較規則及終止時結論，供日後查閱。
> 範圍限制：本輪僅研究網站／公開功能／授權與整合可行性；未修改程式、資料庫、migration、設定或部署。使用者已要求暫停，不再繼續評估或進入實作。

## 一、共同產品目標與淘汰條件

Travel-Companion 希望在每日行程的天氣卡片中，提供可點擊的外部連結，讓使用者直接看到**對應地點、具圖形化呈現的天氣預報**。評估時需區分「一般使用者可免費瀏覽網站」與「開發者可免費、合法、穩定地自動建立地點連結／使用 API」兩件事。

### 硬性限制

1. 排除已確認需要固定費用或僅提供限期試用的方案。
2. 不得把未確認的免費額度、API、URL 規則、嵌入能力寫成已支援。
3. 優先使用穩定、可直接指向具名地點的 URL；不能依賴不穩定的搜尋結果第一筆或只顯示經緯度的頁面。
4. 不應為此新增高維護成本的後端、資料表、排程、付費 API 或額外金鑰管理；如確實需要，明確列出成本與風險。
5. 無法找到合格外部地點頁時，既有 Open-Meteo 來源連結仍需保留作 fallback。
6. 只做評估，不可自行修改 Travel-Companion 程式或部署。

### 每個網站都必須回答

- **具名地點能力**：可否從城市、地址、景點名稱或座標穩定連到正確地點？是否有官方 URL 格式／穩定 ID？
- **圖形化預報**：實際頁面包含什麼（逐時、逐日、圖表、地圖、天氣圖層）？是否需登入、Cookie 或額外操作？
- **免費及商用條件**：一般瀏覽、分享連結、API、自動化、嵌入是否分別免費？是否有固定費用、試用期、配額、歸屬標示或商用限制？
- **整合方式**：只建立外部連結即可，還是必須呼叫 API／解析 HTML／保存 ID 或座標？是否允許深層連結？
- **穩定性與風險**：URL 是否可重現、是否有地區／語言限制、重導向、機器人阻擋、條款變更或反爬風險？
- **維護與安全**：是否需要新增 DB 欄位／快取／排程／Secrets？是否會把使用者輸入直接拼進 URL？如何驗證 host？
- **測試矩陣**：至少測試「台灣士林」、「日本京都」、「中文具名景點（如士林夜市或京都站）」、「座標點」、「同名地點」；記錄日期、URL、實際顯示結果及證據。
- **結論**：列出優缺點、排名（僅該網站的單項評估可給暫定適配分，不可冒充三站總排名）、可行性（高／中／低）、待判斷項目、是否符合硬性條件及建議去留。

### 本站最重要的評估重點

1. 驗證官方支援的地名頁 URL 格式，是否需要 slug、Geocoding ID 或其他參數。
2. 優先用一般瀏覽器驗證士林 ID-backed 頁面：是否正常開啟、地名與國家是否正確、逐時／逐日圖表是否完整載入。先前 fetch 結果有頁面內容但回報 HTTP 404、圖表停在 Loading，故此項**尚未通過**。
3. 比較東京等已能顯示地名與預報的頁面，以及座標頁；座標頁只有經緯度不能算成功。
4. 驗證同名地點、中文景點名稱無候選時的行為，不能盲目採用第一筆或自行猜地名。
5. 評估 Open-Meteo Geocoding 的免費使用條件、配額／限制與在本產品情境下是否允許使用。
6. 評估是否能以最小變更實現；目前既有評估建議把 Drizz.li URL／配對資訊與 Open-Meteo `source_url` 分開保存，並在座標更新／到期時使配對快取失效。

### 已知基線（不可重複宣稱為新驗證）

- 東京地名頁在 2026-10-20 的公開端點測試中回傳 HTTP 200，顯示地名及逐時／逐日預報。
- 士林 Geocoding 候選距離測試約 306 m，符合已定案的直線距離 ≤ 1,000 m 規則。
- 士林 ID 路徑仍待一般瀏覽器確認；座標路徑只顯示座標，不符合需求。
- 既定產品規則：最近候選距離 ≤ 1,000 m 才算匹配；沒有合格頁面時保留 Open-Meteo；不得覆寫 Open-Meteo `source_url`。

2. **若 Travel-Companion 屬商業產品，現階段三站都不能直接判為符合全部硬性條件。** Drizz.li 所需的 Open-Meteo Geocoding／天氣免費 API 不允許商業用途，而商業 API 為固定月費、依條件排除；meteoblue 商業使用需協議／事先許可且費用未公開；Weather.com API 只提供限期試用或固定月費，且純連結授權未確認。
3. 不論候選，中文景點查詢無結果、最近候選超過 1,000 m、查詢失敗或只有座標頁時，都必須保留既有 Open-Meteo 來源連結；不得覆寫 `source_url`。配對仍只按直線距離 ≤ 1,000 m，最近候選優先，不另設名稱／國家／行政區為必要門檻。
4. 本輪完成的是**評估與文件整理，不是實作授權**。評估期間沒有修改應用程式、資料庫、migration、正式設定或部署；依使用者後續指示，已將相關天氣文件整理後另行 commit/push，未執行 tag、merge 或部署。
