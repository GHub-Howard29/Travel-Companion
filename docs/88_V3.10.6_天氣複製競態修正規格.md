# V3.10.6 天氣複製競態修正規格

## 目的

修正行程卡片複製到其他 Day 後，前端可能在 Trip 雲端資料完成可讀取前重複發出天氣請求，造成 `WEATHER_CARD_NOT_FOUND` 或將租約更新中的狀態誤顯示為暫時無法取得天氣。

## 本次處理

- 同一份 Trip／卡片／日期快照只保留一個進行中的天氣請求，避免複製後多次 render 放大請求。
- Edge Function 明確回傳 `WEATHER_REFRESH_IN_PROGRESS` 與 `waiting`，不再把租約由其他請求持有時直接當成快取失敗。
- 前端只對同步／更新中的結果做一次短暫重試；不建立新資料表、佇列、migration，也不調整既有六小時背景刷新規則。
- PWA 更新接管沿用 V3.9 已驗證方案，但本次才以 3.10.6 版本正式納入並驗證；3.10.5 不代表本次新機制。
- 保留 `WEATHER_CARD_NOT_FOUND` 的安全診斷碼與 opaque trace ID，不記錄 Trip 內容、place ID、Authorization 或 provider 原始回應。

## 驗證界線

1. 本機靜態契約、TypeScript 與 production build 必須通過。
2. 本機需驗證新增一張有地點卡片後，複製到多個 Day，每張卡片均能收到對應日期結果；重複儲存不得產生無限請求。此項已通過。
3. RC 實機已驗證由第一天複製到後續天數、由最後一天複製回第一天，以及超過 10 天不提供預報；此項已通過。
4. 正式環境仍須以具資格的真實行程完成發布後單卡與跨 Day 天氣端到端驗收；OPTIONS 200、未授權 401、空結果或單純 Edge Function HTTP 200 不算通過。
