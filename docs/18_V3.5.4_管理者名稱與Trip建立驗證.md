## 實作範圍

- 新增 `admin_profiles`，以 Auth `user_id` 為主鍵，保存最新 Email、固定顯示名稱、`include_in_new_trip` 與 `sort_order`。
- `admin_users` 繼續作為唯一授權來源；`admin_profiles` 不參與角色判斷。
- `admin_profiles` 明確撤銷 `anon` 權限，只向 `authenticated` 授予 CRUD table grants，並以四項 RLS policy 限制為 `super_admin`。
- migration 只為現有兩個 Auth-backed `super_admin` 初始化 profile；`trip_editor` 不建立 profile、不預帶入參與者。既有旅程參與者資料已確認固定映射與排序為 `Howard`（第 1）及 `Carol`（第 2），之後可由 `super_admin` 維護。
- 每次開啟新增旅程表單時在線讀取最新 profile，並依 `include_in_new_trip`、`sort_order` 預帶入 `名稱=Email` 參與者；可編輯者 Email 保持空白。
- 新 Trip ID 固定為 `free-travel-YYYY-MM-DD` 或 `group-tour-YYYY-MM-DD`。既有 Trip ID 與後續編輯行為不變。
- 新增流程先檢查在線狀態、本機／已載入 Trip，再查詢 Supabase；確認無重複後使用 `insert`。雲端成功後才寫入 localStorage，並保留資料庫主鍵作為併發最後防線。

## 修改邊界

- 沒有新增或調整表單版面，僅改變既有欄位的預帶入資料與錯誤處理，因此不需要新的 UI 模擬圖。
- 既有 Trip 更新仍使用 `upsert`；只有「新增旅程」改為不可覆寫的 `insert`。
- 既有 Trip 離線瀏覽、清單／資料／記帳等既有離線能力不變；只有新增 Trip 必須在線。
- 已同步 V3.5.4 App 版本 metadata 與版本歷史；已完成合併、建立 `v3.5.4` tag 及部署。
