# V3.5.3 前端瀏覽器安全防護驗證

> 建立日期：2026-08-26
>
> 狀態：開發中，尚未發布

## 一、修改邊界

- 不修改 Supabase schema、migration、資料列權限（RLS）或角色矩陣。
- 不修改 Trip、Offline First、同步佇列、附件儲存或 Excel 匯出資料流。
- 不修改 GitHub Pages base path、PWA scope、start URL 或 Service Worker 更新策略。
- 僅處理瀏覽器安全邊界、正式 build 的安全政策與必要回歸。

## 二、安全修正

- 正式 build 加入 Content Security Policy（CSP，內容安全政策）；開發模式不強制 CSP，避免阻擋 Vite 開發連線。
- `script-src` 僅允許同源程式，不開放 `unsafe-inline` 或 `unsafe-eval`。
- Supabase API 與 Realtime 僅依 `VITE_SUPABASE_URL` 產生 HTTPS／WebSocket 連線來源。
- 保留 PWA、Service Worker、附件與 App 圖片所需的同源、`blob:` 與 `data:` 範圍。
- Referrer Policy 設為 `no-referrer`。
- iOS standalone PWA 啟動偵測改為同源外部程式，維持 React 啟動前執行。
- OAuth 等待畫面移除 `innerHTML`，改用 DOM API 與 `textContent`。
- OAuth 導向網址限制為目前設定的 Supabase origin。
- 地圖、文字連結與附件視窗統一驗證 HTTP／HTTPS 並隔離 `window.opener`。
- 使用者內容中的 URL 會拒絕非 HTTP／HTTPS、無效網址及含帳號密碼的網址。

## 三、GitHub Pages 限制

- CSP meta 無法使用 Report-Only、`frame-ancestors` 或回報端點。
- Permissions Policy 必須由 HTTP response header 提供；本專案目前的 GitHub Pages 部署無自訂 header 設定，因此本版不加入無效 meta。
- `frame-src 'none'` 僅禁止 App 載入子 frame，不能取代 `frame-ancestors` 的防嵌入能力。

## 五、目前驗證結果

- 修改前基準：`npm run lint`、`npm run build` 通過。
- 修改後：`npm run lint`、版本歷史、TypeScript、Vite PWA build 與 postbuild 安全檢查通過。
- 正式 HTML HTTP 回應已確認包含 CSP、`no-referrer`、同源 iOS 啟動程式、Supabase HTTPS 與 Realtime WebSocket 來源。
- 本機既有 Service Worker 會先呈現舊版快取，符合現行更新機制的既有行為；隔離連接埠後，內建測試瀏覽器無法附加新頁面，因此本次不將 CSP Console 或登入後互動誤列為通過。
