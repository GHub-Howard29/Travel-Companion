# V3.5.6 版本更新最低支援版本機制與手機文字選色工具列修正

> 狀態：發布前驗證已通過；待手動合併、建立 tag 與部署
>
> 版本：V3.5.6（Patch／版本政策橋接版與手機操作修正）；建立日期：2026-08-27；文字選色工具列修正定案日期：2026-08-28

## 目標

避免使用者停留在舊版、略過中間的必要強制更新後，直接遇到最新非強制版本而選擇「稍後更新」。所有低於最低支援版本的 App，無論最新功能版本是否可稍後更新，都必須先完成更新。

另修正 V3.5.5 局部文字套色工具在手機上被系統原生文字選取選單遮住的操作問題：將文字輸入框上方的「A」選色按鈕與提示詞整塊移到文字輸入框下方，其餘選取、套色與顯示行為維持不變。

本版只調整 PWA 版本政策、更新判斷、提示與驗證，以及上述兩個既有富文字編輯欄位的工具列位置；不改變 Trip、Supabase schema、RLS、角色、資料格式或既有 Offline First 資料流。

## 手機文字選色工具列修正

V3.5.5 的資訊卡片「內容」與每日詳細行程「說明」共用同一文字顏色編輯器。目前「A」選色按鈕與提示詞位於文字輸入框上方；Android／手機長按選取文字後，系統原生的剪下、複製、貼上等選取選單可能覆蓋整個工具列，導致使用者無法點選文字顏色功能。

定案修改如下：

- 將「A」選色按鈕與提示詞所在的整個工具列，由文字輸入框上方移到文字輸入框下方；資訊卡片「內容」與每日詳細行程「說明」兩處共用相同行為。
- 保留瀏覽器／作業系統原生長按選取、反白文字與選取控制點，使用者必須能繼續確認實際選取範圍。
- 不加入點選「A」後清除反白、移除 Selection 或隱藏系統選取選單的處理。
- 「A」按鈕、提示文案、色票、局部套色、既有選取範圍保存、儲存、重載、離線同步與各角色閱讀結果均維持原有行為。
- 工具列改到下方後，分隔線應改位於工具列上緣；除位置與必要的分隔線方向外，不重新設計其他畫面、按鈕或互動。
- 本項目只處理網頁可控制的工具列位置；Android／iOS 系統原生選取選單的內容、大小與顯示位置不在 App 控制範圍內。

## 行程時間格式與排序修正

V3.5.5 的行程排序只辨識半形冒號時間，例如 `08:00`；手機中文輸入法可能輸入全形冒號，例如 `08：00`，使該活動被視為沒有有效到達時間並排到最下方。離開時間自動沿用仍會正常，因為該流程只複製字串、不解析時間。

定案修改如下：

- 到達與離開時間接受半形冒號 `:` 或全形冒號 `：`，有效範圍維持 `00:00` 至 `23:59`。
- 不接受冒號前後空白；例如 `08 : 00` 與 `08 ： 00` 均視為無效時間。
- 有效時間儲存時統一正規化為補零的半形 `HH:mm`，例如 `8：00` 儲存為 `08:00`。
- 排序解析必須相容既有全形冒號資料，讓既有活動不必重新編輯即可依到達時間顯示於正確位置。
- 到達時間與離開時間維持可留空；空白欄位依既有規則處理，不視為格式錯誤。
- 同一天內若到達與離開時間皆有填寫，離開時間不得早於到達時間；違反時指出離開時間錯誤並禁止儲存。
- 新增或編輯活動時，只要任一非空白時間欄位含非數字、錯誤符號、冒號旁空白、缺少時或分，或超出 `00:00` 至 `23:59`，必須顯示明確的格式錯誤提示並禁止儲存，不得讓錯誤資料進入排序。
- 錯誤提示必須指出「到達時間」或「離開時間」哪個欄位有誤，範例只使用半形冒號格式（例如 `08:00`），另以文字說明半形或全形冒號皆可且冒號前後不可空格；表單保持開啟並保留使用者已輸入的其他內容，讓使用者可以直接修正。
- 既有雲端或本機資料若已含歷史無效時間，讀取時不得造成頁面錯誤；仍暫時置於有效時間活動下方並維持相對順序，但使用者編輯該活動時必須先修正時間才能再次儲存。

## 已確認的缺口

目前 `useAppUpdate` 僅在 Service Worker 回報可更新時讀取最新版 `app-version.json`，並直接使用其中的 `forceUpdate`。它不會查詢已發布版本的強制更新歷史，也不比較執行中的 `APP_VERSION` 與最低可接受版本。

因此，使用者若仍在 V3.5.0，而最新版本為 V3.5.5 且 `forceUpdate: false`，即使 V3.5.1 曾要求強制更新，舊版仍可能看到「稍後更新」。此外，目前更新提示僅限已安裝 PWA／iOS 顯示，強制更新不應受此限制。

## 版本政策資料契約

公開的 `app-version.json` 新增下列欄位：

```json
{
  "version": "3.5.6",
  "minimumSupportedVersion": "3.5.6",
  "forceUpdate": true
}
```

- `version`：可取得的最新版本。
- `minimumSupportedVersion`：仍可繼續使用 App 的最低執行版本；此欄位是新邏輯的唯一強制判斷依據。
- `forceUpdate`：橋接期間保留為舊版相容旗標。舊 App 不認識 `minimumSupportedVersion`，會繼續讀取此欄位，因此在橋接期間必須維持 `true`。

新程式不直接把 raw `forceUpdate` 當成所有使用者都必須更新的結果，而是計算 `isMandatoryForCurrentClient`：

```text
若 metadata 有 minimumSupportedVersion：
  isMandatoryForCurrentClient = APP_VERSION < minimumSupportedVersion
否則：
  isMandatoryForCurrentClient = metadata.forceUpdate
```

版本比較採三段式語意版號數值比較，不得使用字串排序；格式不合法或 metadata 缺欄位時必須安全失敗，不可錯誤宣告已符合最低版本。

## 橋接與相容策略

只加入新欄位無法修正已安裝的歷史版本，因為它們不會解析該欄位。V3.5.6 必須作為版本政策橋接版，且在 V3.5.6 之後的每個公開 metadata 都維持：

```json
{
  "forceUpdate": true,
  "minimumSupportedVersion": "3.5.6"
}
```

結果如下：

| 執行中的 App | 最新 metadata | 應有結果 |
|---|---|---|
| V3.5.5 或更舊的舊邏輯 | `forceUpdate: true` | 視為必要更新，沒有「稍後更新」。 |
| V3.5.6 或以上的新邏輯 | `minimumSupportedVersion: 3.5.6` | 已達最低版本；遇到後續一般更新可選擇「稍後更新」。 |
| 低於未來提高後的最低版本 | 更高的 `minimumSupportedVersion` | 視為必要更新，沒有「稍後更新」。 |

此相容旗標應持續保留，直到 Product Owner 依實際安裝版本資料明確決定淘汰極舊客戶端。若未來把 `forceUpdate` 改回 `false`，完全沒有執行過橋接版的舊 App 仍可能再次繞過最低版本規則。

## 執行時更新流程

1. App 啟動、從背景回到前景，以及 Service Worker 回報可更新時，都以 `cache: "no-store"` 讀取版本政策。
2. 版本政策與目前編譯的 `APP_VERSION` 比較後，先產生「必要／一般／無更新」狀態；不可使用 `localStorage` 的已讀版本作為必要更新判斷。
3. 必要更新在所有模式都顯示，包括一般桌面瀏覽器；它不受 `dismissedRef`、既有「稍後更新」或已讀更新說明影響。
4. 必要更新提示不提供關閉、叉號或「稍後更新」。一般更新保留既有兩個操作。
5. 必要更新已判定但尚未取得可接管的新版 Service Worker 時，顯示「需要網路才能完成更新」與重試；不可因離線而放行舊版繼續使用。
6. 只有新版 Service Worker 已接管且頁面重載成功後，才可寫入已讀版本與解除必要更新狀態。
7. `onNeedRefresh` 之外也必須能觸發版本檢查，避免沒有收到 Workbox 事件時漏掉政策更新。

## 預計調整範圍

- `src/hooks/useAppUpdate.ts`：讀取版本政策、語意版號比較、必要更新狀態、啟動／前景檢查、離線重試與 Service Worker 接管控制。
- `src/components/UpdatePrompt.tsx`：以「對目前客戶端是否必要」決定提示文案、按鈕與關閉行為。
- `src/config/appVersion.ts`、`public/app-version.json`：新增最低支援版本與橋接相容設定。
- `src/config/versionHistory.ts`、`src/components/VersionInfoModal.tsx`：正確呈現實際版本政策，不把相容旗標誤顯示為所有已更新客戶端的重大更新。
- `scripts/verify-release-history.mjs` 或新增專項腳本：驗證 metadata 欄位、版號比較、最低支援版本不倒退與橋接旗標。
- `src/components/RichTextColorEditor.tsx`：只調整共用文字輸入區與選色工具列的排列順序及必要分隔線方向；不得清除或隱藏原生文字反白。
- `src/utils/itineraryTime.ts`、`src/components/ItineraryPage.tsx`：共用全形／半形冒號解析、有效時間正規化與依到達時間排序；明確拒絕冒號旁空白。
- `scripts/verify-itinerary-time.mjs`：驗證半形、全形、補零、冒號旁空白、無效時間與穩定排序案例。

## 驗收與回歸矩陣

| 情境 | 預期結果 |
|---|---|
| V3.5.5 以下直接開啟最新版 metadata | 必要更新，沒有「稍後更新」。 |
| V3.5.6 遇到 V3.5.7 一般功能更新 | 可選擇「稍後更新」。 |
| 已按過一般更新的「稍後更新」，之後政策提高最低支援版本 | 同一工作階段重新顯示必要更新，不能被既有 dismiss 狀態隱藏。 |
| 一般桌面瀏覽器低於最低支援版本 | 也顯示必要更新。 |
| 低於最低支援版本且離線 | 顯示阻擋與重試；恢復連線後可完成更新。 |
| metadata 格式錯誤、版本號格式錯誤、最新版本倒退 | 不把使用者錯誤標記為已更新；記錄可診斷錯誤。 |
| 新版 Service Worker 尚未接管 | 不寫入已讀最新版，保留必要更新提示與重試。 |
| V3.5.6 以上已達最低版本 | 更新說明、版本歷史與一般更新「稍後」流程維持既有行為。 |
| Android／iOS 長按選取資訊卡片「內容」或每日行程「說明」文字 | 系統選取選單顯示時，移到輸入框下方的「A」選色工具列仍可操作；反白文字與選取控制點保留。 |
| 手機選取局部文字後開啟色盤並套色 | 只有原選取片段套用指定顏色；套色、儲存、重載、離線同步及角色閱讀結果與 V3.5.5 相容。 |
| 桌面版滑鼠選取局部文字 | 工具列位於輸入框下方，選取與套色功能正常，其他欄位及互動沒有改變。 |
| 到達時間為 `08：00`、另一活動為 `15:00` | `08：00` 可被解析並排在 `15:00` 前；下次儲存後正規化為 `08:00`。 |
| 新增／編輯時輸入 `08 : 00`、`08-00`、`上午八點`、`24:00` 或 `08:60` | 顯示對應欄位的格式錯誤與正確範例，保留表單內容且禁止儲存，不進入排序。 |
| 同一天到達時間為 `08:00`、離開時間為 `06:00` | 指出離開時間不得早於到達時間，保留表單內容且禁止儲存。 |
| 到達或離開時間留空 | 不顯示格式錯誤，依既有空白時間及離開時間自動沿用規則處理。 |
| 載入歷史無效時間資料 | 頁面仍可顯示，該活動暫時置於有效時間活動下方；進入編輯後未修正前不得儲存。 |
