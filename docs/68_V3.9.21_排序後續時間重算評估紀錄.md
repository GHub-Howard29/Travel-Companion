# V3.9.21 排序後續時間重算評估紀錄

> 狀態：原 V3.9.20 計畫於 2026-09-30 順延為 V3.9.21。須待 V3.9.19 正式發布完成、V3.9.20「其他資訊自訂子類別」完成後，再進行詳細 UI、規則、費用與影響評估；目前不是可實作規格。

## 分版決策

- V3.9.21 不與 V3.9.20「其他資訊自訂子類別」合併。
- V3.9.20 完成 UI 核准、實作與驗證後，才重新展開 V3.9.21 討論。
- 未完成規則與 UI 定案前，不得修改排序、時間調整、路線快取或 Google Routes 查詢。

## 已記錄的問題

1. 目前調整順序只改變卡片順序，時間不會跟著重整。
2. 既有「調整時間」會保留各站原停留時間，但將後續到達時間依移動時間逐站重算並向上進位到半小時，容易使整日預設時間大幅變動。
3. 排序後若自動重查新相鄰路線，須區分快取命中、開車／步行與大眾運輸的時間依賴，並控制 Google Routes 額度與費用。
4. 排序後的自動預覽與旅途中臨時延誤的時間重算是兩種使用目的，不能在尚未驗證前直接刪除既有入口。

## 下一輪必須討論

- 排序完成後自動開啟預覽，或由使用者按「預覽新時間」。
- 起算錨點、固定時間活動、彈性活動與原停留時間的保留規則。
- 到達時間不進位、五分鐘進位或其他規則；不得直接沿用半小時進位而不重新評估。
- 只重算受影響相鄰區段，或重算後續／全日；查詢前如何顯示可能使用的額度。
- 路線快取命中、缺少 Place ID、航班、跨午夜、無網路、API 失敗與每日上限的停止／降級行為。
- 「調整時間」保留、改名為「重算後續時間」、收進更多操作或與排序後預覽共用入口。
- 預覽中如何呈現原時間、新時間、路線來源、固定時間衝突及取消／套用。

## 現階段傾向但尚未定案

- 排序儲存後只建立非破壞性預覽，不直接覆寫時間。
- 優先沿用有效快取，只查詢新產生或已失效的相鄰路線。
- 套用前由使用者確認；遇到固定時間衝突、航班、跨午夜或必要路線缺失時停止並指出原因。
- 既有入口暫不取消，待共用預覽流程完成實測後再評估去留。

以上方向僅供下一輪討論，不代表 Product Owner 已核准演算法或實作。
