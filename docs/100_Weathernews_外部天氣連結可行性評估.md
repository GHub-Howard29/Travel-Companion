# Weathernews 外部天氣連結可行性評估與實測紀錄

> 實測日期：2026-10-20（台灣時間）
> 狀態：**網站深連結技術面初步通過，整體為「附條件保留」；授權條款仍未確認，不可據此進入整合。**
> 範圍：評估 Weathernews（ウェザーニュース）作為 Travel-Companion 行程天氣卡片的外部圖形化預報連結。只檢查公開網頁與條款線索；未修改程式、資料庫、migration、設定或部署，未 commit/push。

## 一、結論摘要

Weathernews 值得保留為候選，且本輪實測結果優於先前初步預期：台灣士林夜市、台北 101、台北城市、日本京都城市、京都市行政區及小豆島町都找到可直接開啟、可讀取逐時預報內容的具名頁面。已測頁面回傳 HTTP 200，內容包含天氣圖示、逐時降水、氣溫、風速；日本京都頁另有 10 日預報資訊。

但「具名地點頁可用」不等於「可合法把任意行程地點自動轉成 URL」。精確「士林」嘗試路徑回傳 HTTP 404；京都車站尚未找到可證實的具名頁；沒有找到官方公開的任意地點 URL 產生規格或座標 URL 契約。更重要的是，Weathernews.jp 的適用使用條款尚未確認：Weathernews 公司網站的英文及日文條款都明確排除 `https://weathernews.jp/`，因此不能把那些條款直接套用到本評估的天氣網站。

**暫定判斷：技術可行性中高；整體採用可行性中等、附條件保留。** 僅建議繼續確認官方網站的實際適用條款與地點 URL 規則；不建議現在就實作。

### 測試方式與限制

- 以公開頁面 HTTP 擷取確認回應狀態、頁面標題、麵包屑及預報資料；本輪未能使用 Open Browser Use 的真實瀏覽器自動化（服務端回報找不到可連線的 browser socket）。
- 這不是使用者現有 Chrome profile 的手動互動測試，也未驗證 Cookie 清除、跨 IP／地區、手機新分頁或長期 URL 持續性。
- 頁面呈現的預報數值會隨時間更新；本紀錄重點是地點辨識、URL 與內容結構，不把擷取時的天氣數值當作固定資料。
- 小豆島頁的路徑包含 `kanagawa/37324`，但頁面名稱為香川縣小豆島町。這顯示不能僅憑 URL 路徑文字推定行政區正確；須以頁面標題／麵包屑或官方 URL 產生方式驗證。

## 三、URL 與地點解析判斷

### 已知可行的路由形式（僅為觀察到的範例，不是官方 URL 契約）

- 海外具名城市：`/onebox/tenki/world/1/taiwan/taipei/`
- 海外具名景點：`/onebox/tenki/world/1/taiwan/shilin-night-market/`
- 日本城市：`/onebox/tenki/kyoto/`
- 日本城市行政區／地點 ID：`/onebox/tenki/kyoto/26100/`

實測證明部分已知 slug／ID URL 可用，但未找到官方文件承諾這些路徑可由任意地名、地址或座標穩定產生。不得把 `地名轉小寫／連字號` 當作通用生成規則：直接試探的 `.../taiwan/shilin/` 回傳 404。

### 對 Travel-Companion 的意義

1. 如果行程地點恰好對應已確認的 Weathernews 具名 URL，技術上可直接提供外部連結。
2. 不能只用 slug 猜測任意地點 URL，也不應把非官方頁面爬取、隱藏 API 或搜尋第一筆作為自動化方案。
3. 若無可驗證的正確具名頁，應維持現有 Open-Meteo 來源連結，不可用錯誤地點頁取代。
4. 若未來要自動建立 Weathernews URL，應先取得官方可用的地點搜尋／穩定 ID 規則或書面說明；本輪不提出 DB/schema 變更。

## 六、外部連結呈現方式（定案）

- 行程天氣卡片中的外部連結，固定顯示為 **「Weathernews 預報」**，採一般超連結樣式。
- 顯示文字不附加景點名稱、行政區、城市／縣級層級或「精確／附近／區域」等定位描述；不需要為了連結文字而區分 P3、P2、A2 或 A1。
- 超連結實際目的地仍使用該行程地點依既定方案產生並核實的 Weathernews 預報網址。文字簡化不代表可以使用錯誤地點或未驗證的網址。
- Travel-Companion 既有行程天氣仍使用 Open-Meteo；Weathernews 僅作為額外外部預報連結，不取代或改變原有資料來源。
- 不需要額外顯示資料來源宣告、外連確認提示或地點精度說明；點選「Weathernews 預報」即開啟對應外部預報頁。
- 本呈現決策僅定義連結文字與互動方式，不代表 Weathernews.jp 的使用條款、深連結政策或授權問題已獲確認；相關採用條件仍須依本文件評估結果處理。

### 7.4 測試結果解讀

1. 本輪新增至少兩個可確認的設施級精確頁（高松站、高松空港），並取得兩個具名 POI 座標頁候選（道後溫泉、松山城）。此結果較 2026-10-20 的搜尋資料完整。

以本輪四國行程脈絡的 9 個測試目標作適配統計（高松站、高松空港、琴平／金刀比羅宮、小豆島、道後溫泉、松山市／松山城、新居濱市；小豆島另檢查小豆島町與土庄町兩個自治體頁），需區分 POI 與區域結果，不混算單一命中率：

## 八、同一地圖座標連結 Weathernews 的方案評估（2026-10-30）

### 8.1 使用者提出的方案

目前 Travel-Companion 的行程天氣，是依照地圖設定地點取得／使用該地點座標，再由既有天氣服務提供預報。新增評估方向：**沿用同一筆地圖地點的緯度、經度，另行開啟 Weathernews 對應位置的圖形化預報頁**，而不是重新用景點名稱搜尋、依名稱猜 URL，或使用手機當下 GPS 位置。

此方案定位為外部網站連結，不取代目前的 Open-Meteo 預報、不擷取 Weathernews 預報資料，也不改變現有天氣資料來源。

- Weathernews 官方「ココ検索」說明明確提供「地圖搜尋」：使用者可在地圖上將十字中心對準想查的位置，再查看該點預報；也可輸入地名、車站、地址或公共設施名稱。若只選市區町村，結果是自治體內代表點。來源：https://weathernews.jp/ip/help5/tab_search.html
- Weathernews 官方 FAQ 說明其 Pinpoint 預報採用 1km 網格；同一地名可能因搜尋方法不同而連結到不同緯度經度，導致讀取不同網格的預報。來源：https://weathernews.jp/about_forecast/faq/qa01.html

- Travel-Companion 程式碼核對：`supabase/functions/weather-forecast/index.ts` 的 `getCoordinates()`（約第 142–215 行）先讀取 `weather_place_coordinates` 有效快取；快取未命中時，以 Google Places Details 的 `location.latitude/longitude` 取得座標並寫入 30 天快取；後續 Open-Meteo 預報流程使用同一組座標。前端 `WeatherForecastItem` 型別已包含 `latitude`／`longitude`，`ItineraryPage.tsx` 也已將每張卡片的完整天氣結果保存在 `weatherByCardId`；因此區域外連可直接重用現有天氣結果中的座標，**不需要新增後端 API、資料表、Google Places 呼叫或座標快取**，預估只需增加一個前端外部連結入口及標示。這是程式碼檢視結論，本輪沒有修改程式。
- 本輪以 Windows Chrome 實際開啟熊本城座標裸網址，並對照先前道後溫泉與福岡空港的測試，結果詳見 8.4。座標裸網址雖回傳 HTTP 200，但頁面標題與 canonical 都落在市／行政區層級；福岡空港樣本只有沿用完整搜尋產生的 `q`、`v` 路徑參數，才得到機場標題及 Weathernews spot canonical。道後溫泉即使保留具名標題，canonical 仍指向松山市頁。
- 這代表座標本身可作為位置輸入，但**不能假設 `/onebox/{lat}/{lon}/` 就會保留 POI 身分**；熊本城裸座標實測標題退回熊本市中央區，附 `q` 而不含 `v` 亦相同。`q`／`v` 參數如何產生、是否必要及長期穩定，仍未有官方 URL 契約。
- **低負擔方案可行性：** 若產品只需開啟「該 POI 座標所在區域的 Weathernews 預報」，只需重用既有緯度／經度組成 `/onebox/{lat}/{lon}/` 外部網址，不需新增 API、資料表、後端排程、快取或 POI 名稱對照。若要求頁面標題精確顯示景點名稱，則不能只靠裸座標，需要取得並維護 Weathernews 搜尋結果的動態參數或另做搜尋／驗證流程，負擔與風險明顯增加。
- 因此應把方案界定為**可行的低負擔「區域天氣外連」**，而不是已證實的精確 POI 深連結；是否列入產品待辦，取決於使用者是否接受區域退階且 UI 明確標示。

1. 從 Travel-Companion 真實行程卡片取得 `placeId`，並沿用天氣流程已取得／快取的 Google Places 座標（`weather_place_coordinates`）；不要另做一次名稱地理編碼或重複呼叫 Places API。選取具代表性的 P3、P2、A2 樣本，同時保留地點名稱與行政區。
