## 2. 本版範圍

### 2.1 Excel 匯入解析相容性修正

- 擴充 V1 Excel 匯入時間解析：開始／結束時間接受四位數文字或整數儲存值，統一正規化為 `HH:mm`；例如數值 `900` → `09:00`、`1200` → `12:00`。空白結束時間仍沿用開始時間；無效時分仍拒絕。
- 儲存格正規化避免未知物件被隱式轉為 `[object Object]`；目前程式明確處理基本型別、Rich Text、超連結文字及公式結果。
- 新增 parser regression：數值時間、前導零、空白結束時間、無效時間、公式物件拒絕及 Rich Text 標題還原。
- 重要限制：使用者實際 `Test-3.xlsx` 第 21 列仍在瀏覽器回報「行程名稱：必填，且必須為文字」。目前僅有合成 Rich Text fixture 通過；尚未取得同一真實檔案由瀏覽器解析器產生的 D21 值，不能宣稱真實檔案問題已排除。此項列為本 RC 必須完成的實機驗收／阻擋項目。

### 2.3 共享帳本同步生命週期

- 只有目前頁面類型為 expense／共享帳本頁面時，才載入共享帳本並建立 Realtime 訂閱。
- 移除正常連線下固定 30 秒刷新。
- 保留進入帳本頁的初始讀取、Realtime 事件刷新、Realtime 重新連線成功後補讀，以及回頁／前景補讀。
- 離開帳本頁時解除 Realtime channel、清理相關事件監聽與延遲計時器。
- 使用既有頁面類型判斷，涵蓋自訂側邊欄項目。
- 個人帳本、帳目新增／修改／刪除、離線暫存及附件同步流程不變。

### 2.2 Supabase Auth Health 常態探測

- 移除 `useTripWorkspace` 每 30 秒一次的 `/auth/v1/health` 固定探測，以及無待處理恢復工作時的額外啟動 Health GET。
- 移除無條件 focus／visibility reconciliation；保留必要 Trip 初始雲端載入及 online／offline 網路狀態處理。
- 只有存在 recovery pending 時，才在必要時觸發 Trip reconciliation；只有 reconciliation 確實完成且仍在線時才清除 pending。
- 失敗或未完成時保留 pending，等待後續必要的 online／focus／visibility／Session Ready 事件再嘗試。
- 不新增常態輪詢或複雜重試；不以 Auth Health endpoint 代表 PostgreSQL／Database 健康狀態。

## 3. 明確不在本版範圍

- 不調整行程卡片編輯鎖 15 秒 heartbeat；這是使用者編輯期間的多人協作保護。
- 不調整個人清單、其他資訊、天氣請求、PWA Service Worker 更新檢查或伺服器端天氣 Cron。
- 不因本次盤點而擴大修改其他畫面或正常操作期間的保護機制。
- 不新增 Supabase migration、正式資料庫寫入、Edge Function、Secrets 或 Storage 變更。
- 不執行 GitHub Pages 部署，不合併 `main`，不建立正式版本 Tag。
