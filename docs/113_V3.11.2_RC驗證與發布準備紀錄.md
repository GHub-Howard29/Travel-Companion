## 2. 本版範圍

### 2.1 Excel 匯入解析相容性修正

- 擴充 V1 Excel 匯入時間解析：開始／結束時間接受四位數文字或整數儲存值，統一正規化為 `HH:mm`；例如數值 `900` → `09:00`、`1200` → `12:00`。空白結束時間仍沿用開始時間；無效時分仍拒絕。
- 儲存格正規化避免未知物件被隱式轉為 `[object Object]`；目前程式明確處理基本型別、Rich Text、超連結文字及公式結果。
- 新增 parser regression：數值時間、前導零、空白結束時間、無效時間、公式物件拒絕、Rich Text 標題還原、Hyperlink + Rich Text 標題還原，以及失敗欄位診斷結構。
- Hyperlink + Rich Text 相容：ExcelJS 的 hyperlink `value.text` 若為 Rich Text 物件，合併 `richText[]` 內的文字片段作為標題；`hyperlink` URL 不作為行程名稱。
- 開發除錯診斷：解析失敗時，同次解析結果會保留失敗儲存格的 ExcelJS `cell.type`、`typeof cell.value`、安全結構摘要及 `cell.text`；另分列 hyperlink text／URL 與 cell.text 的型態及摘要。僅 `import.meta.env.DEV` 的開發模式輸出至瀏覽器 console。正式環境不輸出診斷、不增加使用者 UI 欄位或診斷文字，一般使用者只看到既有中文驗證訊息。
- D21 實際匯入錯誤：使用者已確認問題解決，且測試資料庫已成功匯入 3 筆四國 TRIP；本項不再列為程式解析阻擋。Hyperlink + Rich Text 合成 fixture 與 `npm run verify:trip-excel-import` 亦通過。

### 2.3 共享帳本同步生命週期

- 只有目前頁面類型為 expense／共享帳本頁面時，才載入共享帳本並建立 Realtime 訂閱。
- 移除正常連線下固定 30 秒刷新。
- 保留進入帳本頁的初始讀取、Realtime 事件刷新、Realtime 重新連線成功後補讀，以及回頁／前景補讀。
- 離開帳本頁時解除 Realtime channel、清理相關事件監聽與延遲計時器。
- 使用既有頁面類型判斷，涵蓋自訂側邊欄項目。
- 個人帳本、帳目新增／修改／刪除、離線暫存及附件同步流程不變。

### 2.2 Supabase Auth Health 常態探測

- 移除 `useTripWorkspace` 每 30 秒一次的 `/auth/v1/health` 固定探測，以及無待處理恢復工作時的額外啟動 Health GET。
- 移除無條件 focus／visibility reconciliation；保留必要 Trip 初始雲端載入及 online／offline 網路狀態處理。
- 只有存在 recovery pending 時，才在必要時觸發 Trip reconciliation；只有 reconciliation 確實完成且仍在線時才清除 pending。
- 失敗或未完成時保留 pending，等待後續必要的 online／focus／visibility／Session Ready 事件再嘗試。
- 不新增常態輪詢或複雜重試；不以 Auth Health endpoint 代表 PostgreSQL／Database 健康狀態。

1. **共享帳本 (`src/hooks/useExpenseBook.ts`、`src/utils/expenseRealtimeLifecycle.ts`、`src/App.tsx`)**：以帳本頁面啟用狀態控制 Realtime 訂閱；移除 30 秒輪詢；保留 Realtime 變更刷新、Channel 重新訂閱後補讀、focus／online／visible 觸發，以及離頁 timer／listener／Channel cleanup。`scripts/test-expense-realtime-lifecycle.mjs` 已使用 fake timers／mock Channel 驗證無 30 秒輪詢、目標 Trip 事件過濾、錯誤／timeout 後重訂閱補讀、前景／網路事件及離頁清理；既有 A/B CRUD 實機即時同步驗收已通過。這些已完成項目全部沿用，不重跑。
2. **Trip Workspace (`src/hooks/useTripWorkspace.ts`、`src/utils/tripWorkspaceRecoveryLifecycle.ts`)**：移除常態 Auth Health 固定探測及無待處理工作時的額外 Health GET，移除無條件 focus／visibility reconciliation；保留 Session Ready gate、online/offline 狀態、recovery pending、in-flight 去重，以及只有 reconciliation 成功且仍在線才清除 pending。`scripts/test-trip-workspace-recovery-lifecycle.mjs` 已以 fake events／mock reconciliation 驗證 Session Ready、online guard、focus／visible、in-flight 去重、未完成／拒絕／中途離線保留 pending、成功清除及 cleanup。該測試不連線 Supabase、不寫入瀏覽器資料；V3.10.12 原有 strict reconciliation／dirty-pending 驗證沿用，不重做。

#### 仍可構成發布阻擋的唯一驗收缺口

目前只保留一個合併驗收目標：**在確認安全的隔離測試環境下，取得本版網路生命週期改動的最小真實整合證據。**驗收觀察限於：

- 共享帳本：真實瀏覽器中進入帳本頁後正常載入；Realtime 更新仍能反映遠端變更；連線恢復後補讀，不因取消 30 秒輪詢而永久漏掉資料；離開帳本頁後不再維持該頁的 Realtime 訂閱或刷新請求。
- Trip Workspace：初始 Session Ready 後必要 Trip 雲端資料可正常載入；網路中斷時 recovery pending 不會被錯誤清除；網路恢復後必要 reconciliation 能完成；不能因恢復流程把較新的本機／雲端資料以舊快照覆寫。

這是驗證本次程式改動的兩個真實環境風險，不是要求重跑完整 A/B CRUD、個人帳本 CRUD、附件測試或 V3.10.12 的既有同步測試。若唯讀環境盤點後無法證明隔離測試環境安全，先停止任何會寫入資料的實測；不得碰觸現有本機 Supabase／localStorage 既有資料。純唯讀檢查可先進行。

- 若檢查結果乾淨且範圍一致，依 `AGENTS.md` 既有標準發布流程繼續；若發現範圍外變更或歸屬不明，停止合併／tag／部署並回報，先以可追溯方式隔離候選範圍。
- 本檢核不得取代必要 build／回歸驗證，也不得把同一項已通過驗證重複執行；只在程式碼、候選來源或部署內容發生變更時重驗相應項目。
